# 참조 전달 순서 비교 실험

일반 IP-Adapter 참조 경로만 얼굴·헤어 → 귀 → 꼬리 → 의상 순서로 변경했다.
추가 부위가 있으면 귀·꼬리 뒤, 의상 앞에 기존 상대 순서대로 배치한다.
부위가 없으면 건너뛴다. 선화 전용 경로의 순서는 변경하지 않는다.

`reference_order.adapter_references`가 이름/RGB/마스크/강도를 한 묶음으로 반환한다.
인코더 이미지 목록, IP-Adapter 마스크 목록, 강도 목록은 모두 이 묶음에서 만든다.
승인 지문과 후보 JSON의 `regional_reference_names`도 실제 전달 순서를 사용한다.
입력 승인 화면과 실행 로그의 '참조 전달 순서'에서 확인할 수 있다.

부위 원본 조건의 저장 순서, 추출 RGB, 최종 배치 마스크, 프롬프트, 성별, 시드,
생성 횟수 및 강도는 이번 변경으로 바꾸지 않는다.
따라서 기존 마스크 겹침 처리도 그대로 남는다.

**의상을 마지막에 전달하는 것은 마지막에 덧칠하거나 더 높은 우선순위를 주는 작업이 아니다.**
효과는 동일한 입력/설정/시드에서 비교해야 한다. 자동 테스트는 전달 대응만 검증하며 품질 개선을 증명하지 않는다.

[Diffusers IP-Adapter Masking 문서](https://huggingface.co/docs/diffusers/v0.38.0/en/using-diffusers/ip_adapter#masking)는
참조 이미지와 대응하는 마스크·강도를 목록으로 전달하는 예시를 제공한다. 이번 구현도 세 목록의 대응을 함께 유지한다.
