# 사용자 시나리오

이 문서는 캐릭터 기준 이미지를 등록한 사용자가 생성 후보의 유사성을 직접 판단하는 흐름을 정의합니다. 구현 전에 사용자 행동과 프로그램 책임을 먼저 확정하기 위한 문서입니다.

## 현재 확정된 입력

사용자가 직접 입력하는 값은 다음 두 가지입니다.

1. 캐릭터 기준 이미지 한 장
2. 화면 범위 한 가지: 전신, 상반신 또는 얼굴 중심

사용자가 작성하는 생성 문장, 의상 참조, 자세 참조와 배경 입력은 현재 시나리오에 포함하지 않습니다.

## 결과의 단계와 이름

- **캐릭터 기준 이미지(CharacterReferenceImage)**: 닮게 생성해야 할 원본 이미지입니다.
- **캐릭터 생성 후보(CharacterGenerationCandidate)**: 모델 실행은 끝났지만 사용자가 아직 검토하지 않은 임시 이미지입니다.
- **승인된 생성 후보**: 사용자가 기준 이미지와 충분히 유사하다고 판단하여 통과시킨 후보입니다. 별도의 모델 실행 객체를 새로 만들지는 않습니다.

모델 실행이 성공했다는 이유만으로 생성 후보를 최종 결과라고 부르지 않습니다.

생성 후보와 저장 결과의 상태는 다음과 같이 구분합니다.

- `생성 대기`: 아직 후보 생성을 시작하지 않은 상태
- `검토 대기`: 생성된 후보를 사용자가 아직 판단하지 않은 상태
- `거절`: 사용자가 후보를 통과시키지 않은 상태
- `승인`: 사용자가 후보를 통과시킨 상태
- `저장 대기`: 승인됐지만 아직 파일 저장 여부를 결정하지 않은 상태
- `저장 완료`: PNG 이미지와 JSON 결과 기록이 모두 저장된 상태
- `저장 실패`: PNG 또는 JSON 저장에 실패한 상태
- `저장 거절`: 사용자가 파일로 저장하지 않기로 결정한 상태

`미승인`은 검토 전과 거절의 의미가 섞이므로 사용하지 않습니다. `저장 승인`은 상태가 아니라 사용자가 실행하는 동작으로 구분합니다.

## 기본 흐름

```text
캐릭터 기준 이미지 등록
        ↓
화면 범위 선택
        ↓
생성 후보 한 장 생성
        ↓
프로그램의 기술 검사
        ↓
사용자가 기준 이미지와 비교
   ┌────┴────┐
 거절        승인
   ↓          ↓
재생성 여부  저장 대기
 ┌─┴─┐      ┌─┴─────┐
재생성 종료  저장 승인  저장 거절
  ↓             ↓        ↓
새 시드       저장 시도   저장하지 않고 종료
  ↓          ┌──┴──┐
다음 후보   저장 완료 저장 실패
                         ┌──┴────┐
                      다시 저장  저장 거절
```

한 실행에서는 후보를 한 장씩 만들며 최대 3장까지만 시도합니다. 거절한 후보는 자동 저장하거나 자동 삭제하지 않고 해당 실행의 메모리에만 유지합니다. 사용자가 중간 후보를 승인하면 남은 후보는 생성하지 않습니다. 세 후보를 모두 거절하면 `승인 결과 없음`으로 종료합니다.

## 프로그램이 자동으로 검사하는 항목

프로그램은 사실 여부가 명확한 기술 항목만 검사합니다.

- 이미지 후보가 정상적으로 생성됐는가
- 선택한 화면 크기로 생성됐는가
- 모델 실행 오류가 발생하지 않았는가
- 사용한 모델, 시드와 설정이 기록됐는가

기술 검사를 통과해도 캐릭터 유사성이 확인된 것은 아닙니다.

## 사용자가 판단하는 항목

사용자는 기준 이미지와 생성 후보를 직접 비교하여 다음을 판단합니다.

- 같은 캐릭터로 받아들일 수 있는가
- 얼굴, 머리색, 눈과 주요 디자인 특징이 충분히 유지됐는가
- 색감과 전체 분위기가 기준 이미지와 유사한가
- 선택한 화면 범위에 맞게 생성됐는가
- 실제로 사용할 수 있는 품질인가

## 후보 검토 선택

### 승인

기준 이미지와 충분히 유사하면 생성 후보를 사용자 승인 결과로 변경하고 이미지 생성을 종료합니다. 승인은 파일 저장을 뜻하지 않으며 결과는 `저장 대기` 상태가 됩니다.

### 거절

유사하지 않거나 사용할 수 없는 품질이면 현재 후보를 거절합니다. 프로그램은 재생성 여부를 확인하고, 사용자가 재생성을 선택하면 새로운 시드로 다음 후보를 만듭니다. 재생성을 선택하지 않으면 저장하지 않고 종료합니다.

## 임시 보관과 자동 저장 금지

- 생성 후보는 실행 중 시스템 메모리에만 임시 보관합니다.
- 생성 직후에는 PNG와 JSON 파일을 만들지 않습니다.
- 거절한 후보와 저장을 거절한 결과는 디스크에 남기지 않습니다.
- 실행 중에는 최대 3개의 후보를 메모리에서 비교할 수 있습니다.
- 프로그램을 종료하면 저장하지 않은 후보는 유지되지 않습니다.
- 사용자가 후보를 승인하고 저장까지 허용했을 때만 파일을 만듭니다.

## 승인 결과 저장

승인 결과의 기본 저장 위치는 다음과 같습니다.

```text
outputs/approved/YYYY-MM-DD/
```

날짜 폴더는 사용자가 저장을 승인했을 때만 만듭니다. MVP에서는 저장할 때마다 다른 폴더를 선택하는 기능을 제공하지 않습니다.

이미지 파일명은 다음 규칙을 사용합니다.

```text
YYYYMMDD_HHMMSS_{full|upper|face}_{01~03}_seed{숫자}.png
```

화면 범위는 `full`은 전신, `upper`는 상반신, `face`는 얼굴 중심을 뜻합니다. 후보 번호는 해당 실행에서 생성된 순서입니다.

예시는 다음과 같습니다.

```text
20260823_143025_full_01_seed123456.png
```

## 결과 기록 JSON

승인 결과를 다시 추적하고 같은 설정으로 재현할 수 있도록 PNG와 같은 이름의 JSON 파일을 함께 저장합니다.

```text
20260823_143025_full_01_seed123456.png
20260823_143025_full_01_seed123456.json
```

JSON에는 다음 정보만 기록합니다.

- 사용한 기본 모델
- 참조 이미지 파일명
- 화면 범위
- 시드
- 이미지 크기
- 생성 단계 수
- 그림체 적용 강도
- 후보 번호
- 생성 시간
- 사용자 승인 시간

PNG와 JSON이 모두 정상적으로 만들어져야 `저장 완료`로 처리합니다.

## 저장 실패 처리

- PNG 또는 JSON 중 하나라도 저장하지 못하면 `저장 실패`로 처리합니다.
- 저장에 실패해도 승인 결과는 시스템 메모리에 유지합니다.
- 저장 실패는 최대 3회의 이미지 생성 횟수에 포함하지 않습니다.
- 저장 실패 때문에 이미지를 다시 생성하지 않습니다.
- 오류 메시지는 실패 원인과 저장 경로를 한글로 표시합니다.
- 사용자는 `다시 저장` 또는 `저장하지 않기`를 선택합니다.
- 다시 저장에 성공하면 `저장 완료`가 됩니다.
- 저장하지 않기를 선택하면 `저장 거절`로 종료합니다.
- PNG와 JSON 중 하나만 남은 결과는 최종 저장 결과로 인정하지 않습니다.

## 자동 유사도 판정을 사용하지 않는 이유

캐릭터 유사성은 얼굴, 의상, 색감과 분위기를 함께 보는 주관적인 판단입니다. 별도 판정 모델을 추가하면 실행 시간과 메모리 사용이 늘어나며 사용자의 실제 선호와 다른 점수를 낼 수 있습니다.

현재 MVP에서는 자동 유사도 모델을 사용하지 않습니다. 프로그램은 기술적 성공만 검사하고 최종 유사성은 사용자가 결정합니다.

## 실패 사례 기준

다음 결과는 모델 실행이 성공했더라도 사용자가 재생성을 선택할 수 있는 생성 후보입니다.

- 기준 캐릭터와 다른 인물처럼 보임
- 얼굴이나 주요 디자인 특징이 사라짐
- 전신을 선택했지만 머리 또는 발끝이 잘림
- 일부 신체 부위만 과도하게 확대됨
- 그림체나 색감이 기준 이미지와 크게 다름

## 현재 구현과의 차이

현재 GUI는 기준 이미지 등록, 화면 범위 선택과 이미지 한 장 생성까지만 지원합니다. 후보 비교, 승인·거절, 재생성 확인, 저장 확인과 저장 재시도 기능은 아직 구현되지 않았습니다.

## 아직 결정하지 않는 항목

다음 내용은 이 시나리오의 유사성 판정 범위에 포함하지 않습니다.

- 자동 자세·관절 검사 도입 여부
- 의상과 자세 참조 입력 방식

## 확정 결론

프로그램은 이미지 생성의 기술적 성공만 검사합니다. 캐릭터 유사성은 사용자가 생성 후보를 보고 `승인` 또는 `거절`로 결정합니다. 후보는 자동 저장하지 않으며, 승인 후 사용자가 저장을 허용한 결과만 PNG와 JSON으로 함께 저장합니다.
