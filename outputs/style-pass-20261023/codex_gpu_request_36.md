## 판정 (사용자 — Codex는 관찰만)

칸마다 **입력 그림과 변환 그림을 나란히** 놓고 본다.

### 그림체 변화 (캐릭터에서 본다)

| 항목 | 뜻 | 바뀜 / 안 바뀜 |
|---|---|---|
| 선 | 외곽선·안쪽 선의 굵기·유무·형태 | |
| 명암 단계 | 그림자가 몇 단계인지(부드러운 그라데이션 ↔ 2~3단 셀 명암) | |
| 채색 방식 | 칠의 질감(광택·텍스처 ↔ 평평한 칠), 하이라이트 표현 | |

- **배경 채도·밝기만 달라진 것은 변화로 세지 않는다.**
- 그림체 변화 있음 = 셋 중 하나 이상이 캐릭터에서 눈에 띄게 바뀜.

### 동일성 (입력 그림 기준)

| 항목 | 유지 / 깨짐 |
|---|---|
| 얼굴 | |
| 눈색 | |
| 머리색 | |
| 장식(머리 장식·장신구) | |
| 의상 | |

- 다섯 항목이 모두 '유지'여야 동일성 유지다.
- **자동 검사 결과는 동일성 통과로 쓰지 않는다.** 이번 실행기는 자동 특징 검사를 돌리지 않는다(요청 35에서 M7 0.6 실패를 놓쳤다).

### 결과에 따른 처리 (실행 전 고정)

- **후처리 구조 후보로 남김:** 3줄 중 **2줄 이상**에서 그림체 변화 있음 + 동일성 유지가 함께 확인됨.
- **이번 LoRA 검토 종료:** 그 밖의 모든 경우(변화 없음, 동일성 깨짐, 실행 실패).
- 어느 쪽이든 **시험 B·C·다른 LoRA로 자동으로 이어가지 않는다.** 다음은 사용자가 정한다.
- 실패해도 '그림체 변환 자체가 불가능하다', '직접 학습이 필수다'로 넓혀 해석하지 않는다. 결론은 '이 LoRA, 이 조건에서'로 한정한다.

## 추가 대조군 (사용자 결정: 넣지 않음)

- **LoRA 없이 같은 문장**(`variants: ["style", "none"]`): 기준 모델만으로 `Transform into anime.`을 처리한 칸.
- **필요한 결정:** 후처리 후보로 남을 때, 그 효과가 **이 LoRA 덕분인지 기준 모델 자체의 편집 능력인지**를 가른다.
  - 빌린 LoRA는 학습 자료가 공개되지 않아 제품에 쓸 수 없다(D-159). 기준 모델만으로 같은 효과가 나면 후보를 LoRA 없이 설계할 수 있고, LoRA 덕분이면 허가 자료로 만든 LoRA가 있어야 후보가 제품으로 갈 수 있다.
  - 이 결정이 지금 필요 없으면 넣지 않는다. 넣으면 3장 추가(약 1시간 반 추가).

## 중단·기록 규칙

- `memory_stopped` 또는 PyTorch reserved > 6.5GiB → 그 줄 실패로 기록하고 다음 줄. **상한을 완화하지 않는다.**
- 그림체 LoRA SHA 불일치, 어댑터 불러오기·적용 오류 → 그 줄 실패, 오류 전문 보고. 코드·설정을 고치지 않는다.
- 강도·seed·지시문을 바꿔 다시 돌리지 않는다.
