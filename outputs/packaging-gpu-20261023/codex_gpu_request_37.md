**예정된 거절 — 이유까지 대조:**

- 한계: 그 검사 안에서 보호 영역과 얼굴 영역 중 **어느 쪽이 비었는지는 개발 기록에 남아 있지 않다**(문구가 같음). 이 구분까지 필요하면 개발 환경 진단 실행이 필요하다 — 자동으로 하지 않고 제안만 한다.

**배열이 다를 때 — 실질적 차이 확인:**
- 실행기가 차이 근거를 남긴다(`rows.<건>.evidence`):
  - 보호 영역(머리·얼굴·장식)과 얼굴 영역마다 개발/후보 픽셀 수, 겹침 비율(IoU), 빠진 픽셀·더해진 픽셀.
  - 경계에서 3픽셀보다 먼 차이를 따로 센다. **먼 누락 = 머리 영역 누락 후보, 먼 추가 = 배경 포함 후보.**
  - 다른 부위별 수치, 겹친 그림 `segment\<건>\diff-protect.png`(초록 둘 다, 빨강 개발에만 = 후보에서 빠짐, 파랑 후보에만 = 새로 들어감).
- Codex가 이 수치·그림과 기존 CPU 비교(요청 34 같은 건의 `result.json` 픽셀 수, 저장된 캔버스)를 보고 판단한다. 실질적 차이가 없다고 근거를 댈 수 있을 때만 검토 기록에 적는다:

  ```json
  {"reviewer": "Codex", "rows": {"B2-base-parts": {"resolution": "no_substantive_difference",
    "evidence": "diff-protect.png: 경계 1~2픽셀만 다름, 먼 누락 0·먼 추가 0, 보호 IoU 0.998"}}}
  ```

- 판단이 서지 않으면 그대로 '검토 필요'로 두고 P5를 시작하지 않는다(보고에 수치·그림 경로).

**P5 시작 조건(실행기가 확인):** `--after-p4 <P4 출력 폴더>` [`--p4-review <검토 기록>`] — 같은 고정 목록으로 돈 실제(dry 아님) P4이고, 프로세스 정상 종료(`normal_exit`), 끝난 뒤 후보 그대로, 예상 밖 실패 0, 검토 필요 건은 모두 근거와 함께 해결. 하나라도 아니면 실행기가 스스로 시작을 거부한다.

## P5 — Qwen 사용자 흐름 2줄 (의상 없음 A3 · 의상 있음 B2)

- 사용자 첫 실행 그대로: 가짜 사용자 폴더에서 **준비 화면 → 모델 폴더 선택 → 깊은 검사 → 기록** → 그 기록으로 작업실 → 줄마다 캐릭터(·의상) 고르고 '이미지 생성' → 끝나면 '저장'.
  - 저장 버튼 누름은 자동 시험 행동이다. 사용자 품질 합격으로 집계하지 않는다.
- 통과: 두 줄 생성·저장 완료, 모든 Qwen 기록 `memory.limit_gib` 6.5 이하이고 최고 reserved ≤ 6.5GiB, `memory_stopped` 없음, 작업 프로세스 Python이 모두 후보 안, 끝난 뒤 후보 파일 목록 그대로.

- 비교(통과 기준과 별도로 기록):

## 차이 구분 — 패키징 문제인가, 생성 변동인가

| 관찰 | 분류 |
|---|---|
| 후보에서만 나는 오류(불러오기 실패·DLL·후보 밖 경로·권한) | **패키징 문제** |

| 모두 같음 | 차이 없음 |

- '원인 미확정'이면 **대조 실행을 제안만 하고 돌리지 않는다**(사용자 승인 필요). 제안할 대조: 이 HEAD 코드·같은 입력·같은 장면 seed·같은 모델 파일·같은 설정 값으로 **런타임만 개발 환경**(개발 venv + `qwen-test-venv`, `configs/qwen_edit_settings.json`)으로 바꾼 한 번. 결과가 후보와 같으면 런타임 문제가 아니다.
- 사용자 지시: 개발 환경을 다시 만드는 일은 기본 절차가 아니다. 대조도 지금 있는 개발 환경을 그대로 쓴다.

## 중단·기록 규칙

- `memory_stopped` 또는 PyTorch reserved > 6.5GiB → 그 줄 실패로 기록하고 다음 줄. **상한을 완화하지 않는다.**
- seed·장면·설정을 바꿔 다시 돌리지 않는다. 실패한 줄을 반복하지 않는다.
- **P5·P6는 이 요청서 범위만.** 재시도는 제품 흐름이 스스로 하는 자동 재시도(요청 34와 같은 규칙)뿐이고, 실행기·사람이 재시도를 더하지 않는다. 개발 환경 대조 실행은 '원인 미확정'이어도 제안만 한다(사용자 승인 전 실행하지 않음).
- 이번 후보의 런타임(내장형 3.10.6)은 바꾸지 않는다. 최종 배포용 Python 검토(INSTALLER_PACKAGING_PREP 4-6)는 이 검증과 별개다.
- **배포 후보 파일을 고쳐야 할 것 같으면 고치지 말고 멈춘다.** 보고에 바꿔야 할 파일·내용과, 그 변경으로 다시 해야 할 검증(P1~P5 중 어느 것)을 적는다.
- 모델 SHA 검사 정책을 바꾸지 않는다(작업 프로세스마다 약 200초 해시 — 그대로).
- 시험용 모델 폴더·기존 설치·공유 캐시를 지우거나 옮기지 않는다. 사용자 허깅페이스 토큰 파일을 읽지 않는다(실행기는 가짜 사용자 폴더를 쓴다).
