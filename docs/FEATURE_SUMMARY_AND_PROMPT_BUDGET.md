# 특징 요약 승인과 프롬프트 예산

## 사용자 흐름

1. 의상 추출 승인 후 WD 분석에서 의상 종류·색·소재·장식에 해당하는 후보만 자동 선택한다.
2. 기본 화면은 추출 이미지, 적용할 의상 특징 요약, 승인/취소다. 체크박스는 상세 수정에 접어둔다.
3. 기준 이미지에서는 의상이 아닌 캐릭터 특징을 자동 선택한다. 배경·구도·인원수는 기본 선택하지 않는다.
4. 기준 이미지와 유지할 특징, 승인된 의상 특징, 실제 토큰 사용량을 확인하고 승인한다.
5. 얼굴·의상 참조 입력 승인 후 생성한다. 기본 모델 로딩 전에 특징/프롬프트 승인을 완료한다.

상세 수정에서 체크를 바꾸면 요약과 프롬프트 예산을 다시 계산한다.
기준 이미지의 기존 의상은 상세 화면에서도 선택하지 못한다.
의상 이미지에서 분류된 인물 특징/배경은 의상 조건에 넣지 않는다.
사용자 지정 성별은 기존처럼 우선하며 외형만으로 성별을 자동 확정하지 않는다.

의상 종류(상의/하의/드레스/전신 의상) 선택 UI는 제거했다.
의상 조건은 참조 이미지에서 추출하고 승인한 특징으로 구성한다.
화면 범위(전신/상반신/얼굴)는 그대로 유지하며, 이를 의상 종류로 변환하지 않는다.
구형 좌표 처리의 의상 종류 enum은 내부 데이터 호환을 위해 남기되,
이미 승인된 값이 없는 구형 경로에서는 임의의 의상 종류를 기본값으로 넣지 않는다.

## 자동 선택의 범위

reference_features.py는 검출기가 아니라 WD 후보를 역할별로 분류하는 제한된 어휘 정책이다.
알려진 명사/태그만 character, garment, scene, context로 분류하며 모르는 태그는 unknown이다.
unknown은 자동 선택하지 않고 요약에 남겨 상세 수정에서 수동 반영할 수 있게 한다.
옷이 아닌 태그를 무조건 캐릭터로 취급하거나, 이미지 안에 없는 특징을 새로 생성하지 않는다.

귀/꼬리 종족과 머리 길이의 경쟁 후보는 원점수 차이 0.10 미만이면 자동 확정하지 않는다.
이 기준은 품질 검증된 분류 확률이 아니라 초기 운용 정책이다.
혼종 캐릭터나 알려지지 않은 장식은 상세 수정이 필요할 수 있다.
태그 누락/오검출을 해결하는 새 비전 모델이나 LLM은 추가하지 않았다.

눈색은 기존 두 크롭 분석을 사용한다.
판단 보류이면 사용자가 색을 하나 이상 선택하거나 눈색을 생략할 것을 확인해야 승인할 수 있다.
여러 색을 선택해도 오드아이 태그를 자동 추가하지 않는다.
눈색의 위치·비율·그라데이션을 보장하지 않는다.

## 토큰 처리

reference_prompt_budget.py는 승인된 캐릭터와 의상 태그 전체를 필수 조건으로 예약한다.
기존 추상 문구 same face/same hairstyle/same eye color/same art style은 자동 추가하지 않는다.
full_body/full body처럼 표기만 다른 중복은 한 번만 반영한다.

생성 화면 범위는 기존 사용자 설정을 따른다. standing/front view/white background를 새로 강제하지 않는다.
기본 품질·주름 표현은 선택 조건이며 남는 공간에 추가한다.
긴 선택 조건이 안 들어가도 뒤의 짧은 조건을 검사하며, 제외 목록을 승인 화면에 표시한다.
필수 조건만으로 한도를 초과하면 PromptBudgetError의 필요 토큰 수와 조건을 보여주고 승인을 막는다.
필수 조건을 조용히 자르거나 토크나이저 최대 길이 숫자를 임의로 늘리지 않는다.

부정 프롬프트는 기존 충돌 제거/길이 제한 정책을 유지한다.
실제 긍정·부정 문장과 원래 부정 조건을 상세 화면에서 확인할 수 있고, 부정 조건 잘림도 기본 화면에 알린다.
GUI는 승인한 긍정·부정 문장 쌍을 저장한다. 생성기는 실제 파이프라인 토크나이저로 다시 구성하여
승인한 쌍과 다르면 추론 전에 중단한다. 모델/토크나이저 변경으로 조건이 달라져도 재승인이 필요하다.

## 로딩과 검증

CPU에서 tokenizer 및 tokenizer_2 파일만 먼저 읽는다. 이 단계는 SDXL 모델 가중치나 CUDA를 로드하지 않는다.
기존 Hugging Face 캐시를 사용하며 토크나이저 파일이 없으면 다운로드가 필요할 수 있다.
자동 테스트는 필수 조건 보존, 두 토크나이저 한도, 역할 분리, 요약/상세 UI,
눈색 보류 확인, 승인 전 모델 차단, 승인 후 문장 변경 차단을 검증한다.

실제 캐시의 Animagine XL 3.1 토크나이저 두 개로 대표 입력 한 건을 별도로 확인했다.
최근 로그 기반 캐릭터 조건(눈색 두 개 포함)과 의상 조건 여섯 개, 전신 구도,
품질 표현 세 개가 각각 64/77 토큰에 들어갔다. 모든 사용자 입력에 대한 결과는 아니다.
실제 WD 재분석이나 GPU 이미지 생성 품질 테스트는 이 변경 검증에 포함하지 않는다.

## 바꾸지 않은 것

초기 RGB 사용 금지, 얼굴·의상 이미지 참조 강도, 인체 복원/자세 제어/부분 보정 비활성 정책은 유지한다.
따라서 이 변경으로 인체 비율이나 눈색 재현까지 해결됐다고 볼 수 없다.
