# 입력부터 결과까지의 흐름

## 1. 입력

- `base.yaml`: 모델, 해상도, 단계 수와 경로
- `prompts.csv`: 요청 번호, 생성 문장, 제외 문장과 시드
- `style.png`: 선택 사항인 참조 그림

## 2. 검사

- Python과 GPU를 사용할 수 있는지 확인합니다.
- SD 1.5는 512×512, Animagine XL 시험은 768×768인지 확인합니다.
- 요청 번호와 시드가 올바른지 확인합니다.
- 참조 그림 사용이 켜져 있으면 파일이 존재하는지 확인합니다.

## 3. 모델 준비

- 설정에서 SD 1.5 또는 Animagine XL을 선택하고 `D:\genai-cache`에서 찾습니다.
- 없으면 공식 모델 저장소에서 한 번 내려받습니다.
- 반정밀도(float16)를 사용합니다. SD 1.5는 GPU에 올리고 Animagine XL은 사용 중인 부분만 GPU로 이동합니다.
- 참조 그림 사용이 켜져 있으면 특징 전달 장치(IP-Adapter)를 연결합니다.

## 4. 순차 생성

```text
첫 번째 요청 → 이미지 저장 → 기록 저장
두 번째 요청 → 이미지 저장 → 기록 저장
세 번째 요청 → 이미지 저장 → 기록 저장
```

각 요청마다 별도의 시드 생성기를 새로 만들어 다른 실행에서도 같은 초기 잡음을 사용합니다. 이미 같은 이름의 PNG가 있으면 완료된 요청으로 보고 건너뜁니다.

## 5. 출력

```text
outputs/실행날짜-시간/
├─ images/
│  ├─ 001_101.png
│  └─ ...
└─ result.json
```

`result.json`은 실행 환경, 설정, 성공·실패 상태, 이미지별 요청과 시간을 저장합니다. 오류가 발생해도 그전까지 만든 이미지와 기록은 남습니다.

## 6. 선택과 재시도

1. 생성된 후보 3장을 직접 확인합니다.
2. 마음에 드는 이미지가 있으면 해당 실행 폴더를 보관합니다.
3. 마음에 드는 이미지가 없으면 실행 폴더 이름을 확인한 뒤 그 폴더만 삭제합니다.
4. 요청 문장이나 시드를 수정하고 다시 실행하여 새 후보 3장을 만듭니다.

프로그램이 기존 결과를 자동 삭제하지 않습니다. 다른 실행 결과를 실수로 지우지 않도록 삭제 대상은 사용자가 확인한 실행 폴더 하나로 제한합니다.

## 실패할 때

- 설정 오류: 잘못된 항목과 고치는 방법을 한글로 표시하고 모델을 불러오기 전에 종료합니다.
- GPU 없음: CPU로 몰래 바꾸지 않고 GPU 확인 방법을 표시합니다.
- GPU 메모리 부족: 해상도나 설정을 자동 변경하지 않고 권장 조치와 결과 폴더를 표시합니다.
- 중간 중단: `--resume`에 기존 결과 폴더를 전달하여 빠진 이미지부터 다시 생성합니다.
