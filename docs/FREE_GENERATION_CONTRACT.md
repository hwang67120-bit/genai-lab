# 자유 생성 단계 계약 (2026-10-14, 사용자 승인 — 결정 5개 모두 권고대로, D-123)

## 결론부터
- 자유 생성 = **기준 이미지 + 확정된 특징표 + 요청(자세·구도·시점·배경·상황 문장, 없으면 무작위 전신 자세) → 새 그림 1장 → 특징 유지 검증 → 사람 승인**. 완성 기준 2단계(새 작품의 동일성: 특징 유지, 픽셀 아님)와 3단계(새로운 연출)를 겨냥한다.
- 편집 단계와 다른 점 하나: **머리를 원본 픽셀로 붙이지 않는다.** 특징표(D-119~121)로 유지 조건을 주고 결과에서 특징을 비교하며, 동일성은 사람이 최종 판정한다. 그래서 결과 쪽 분할이 필요하다.
- 2026-10-14 사용자 승인: 아래 7절의 5개를 모두 권고대로 확정했다(① Qwen 유지 ② 배경 허용 ③ 요청은 연출만 ④ 기준 이미지 둘 다 ⑤ 무작위 자세 고정 목록). 공통 함수 `genai_lab/free_generation_pipeline.py`(`run_free_generation`)와 작업실 자유 생성 버튼을 연결했다. CPU 검증과 GPU 품질 측정은 분리하며 요청 20은 아직 초안이다.

## 2. 모델과 지시문 (결정 ①)
- 권고: 지금 쓰는 **Qwen-Image-Edit-2511(같은 worker, 6.5GiB 상한)**으로 첫 측정. image 1 = 기준 이미지, image 2 = **그 기준 이미지에서 자동 추출한 머리 크롭**(분할 실패 시 전체 기준 이미지). 지시문 = 조건 목록(아래). 크롭은 추가 외부 입력이 아니라 같은 기준의 시각 참조이며, 다른 이미지가 들어오지 않도록 크롭 좌표·픽셀·SHA를 검증한다. 동일성을 보장하지 않는다. 근거: 편집 시험에서 얼굴·머리가 비교적 유지됐고(원본 붙이기 전 Qwen 출력에서 정렬이 되는 수준), 설치·메모리 검증이 끝났다. 대안(생성 모델 + 참조 어댑터)은 설치·메모리·시험이 처음부터라 첫 측정 뒤 필요하면 검토.
- 지시문은 편집과 같은 구조(D-112 조건 목록, 출처·이유 기록). 문자열은 코드 상수 + 특징표 값 + 요청 문장. LLM·RAG 없음.

조건 목록(초안):
| key | 출처 | 문장(초안) |
|---|---|---|
| keep_character | character_features | "Keep the same character: {hair length/style/colour}, {eye colour}, {head accessories}, {skin}. Keep the face the same as in image 1." (unknown 항목은 뺌) |

## 3. 검사(자동)와 판정(사람)
자동(분석 실패는 확인 불가로 결과와 이유를 반환; 확신 있는 특징 위반(검증기 `retry`, D-126 — 경계값·태그와 픽셀 엇갈림·감김/가림·요청과 충돌·구체→일반 태그·의상 태그 차이는 제외) 또는 금지 태그 관찰은 seed 43으로 한 번 재시도. 두 시도가 있으면 결과 목록에서 사람이 고른다. D-127: 자동 '유지'는 '위반 관찰 없음'이며 조건 충족은 사람 판정만; 요청이 가리는 특징(눈 감기 → 눈 색)은 지시문에서 빼고 요청 연출은 태그로 따로 관찰. Qwen 실패·메모리 중단·계약 불일치는 실패로 기록하고 자동 재실행하지 않음):
1. 결과 분할(see-through 분할기, GPU, Qwen 종료 뒤) → 머리카락·얼굴·눈·부위 마스크.
2. 특징 검증(D-121)을 **결과 마스크**로: 머리색·눈 색·피부색 ΔE, 태그 항목, 부위 유무. 분할 연결 요소는 `mask_components` 관찰값으로만 기록한다. 실제 귀·꼬리·날개의 개수·형태·연결·가림은 **확인 불가**로 남겨 사람에게 넘긴다. 요소 수를 실제 개수로 변환하지 않는다.
3. 팔·손 관찰(DWPose, 결과 단독: 인식한 관절 기록, 미검출은 가림·분할 오류·소실을 구분하지 못하므로 확인 불가) — 편집의 원본 대비 검사는 자세가 바뀌므로 쓰지 않는다.
4. 요청 의미: 명백한 외형 변경 지시의 문장 패턴을 거부한다. 단어 출현만으로 외형 변경을 단정하지 않는다(눈 내리는 거리·눈을 감은 표정 허용). 이 유한 검사는 의미 이해 모델이 아니므로 입력에서 사람이 연출 범위를 확인하고, 결과의 요청 반영은 미검토로 남긴다. 배경 표현 후보가 없으면 흰 배경을 명시한다.
5. 안전: 입력에서 성인 캐릭터를 확인하고, 명백한 금지 요청을 거부한다. 결과의 금지된 노출·아동 외형 태그가 강하게 관찰되면 사용을 차단한다. 태그 누락·오탐을 포함해 자동 안전 통과를 보장하지 않으며 미검토는 사람 노출·심한 이상 확인으로 연결한다.

사람 판정(`judgement.json`, D-114 항목 + 1개):
- same_character(최종) / outfit(same·partial·different) / body_parts / pose / severe_defect / **request_followed(yes·partial·no)**.
- 작업실 결과 확인 창 체크: "같은 캐릭터로 보입니다" · "옷이 그대로입니다" · "요청한 연출이 반영됐습니다" · "심하게 이상한 곳이 없습니다".

## 4. 작업실과 외부 API
- 작업실: 캐릭터 선택 후 "기준 이미지로 자유 생성" 버튼(별도 옷 참조 불필요). 승인 편집본은 사용자 승인 `.review.json`과 이미지 SHA를 확인하고, 원본은 별도 종류로 기록한다. 확인 창 = 기준 이미지 · 특징표(수정 가능) · 요청 문장 상자(비우면 무작위 자세 안내) · 지원 범위 경고. 결과 창 = 위 체크 4개 + 특징 검증 요약(kept/changed) 표시.
- 외부 API: 같은 공통 함수(`run_free_generation(...)`), 확인 창 대신 "검토 대기" 반환(D-110). 요청 문장은 API 입력의 한 필드.
- 거부·실패는 항상 알린다(D-104). 그림별 조정 없음.

## 5. 지원 범위와 금지
- 성인 캐릭터만, 노출 의상 규칙, 금지 입력 목록은 그대로. 요청 문장으로 노출·아동 외형을 만드는 시도는 거부.
- 편집 단계의 지원 범위 밖(앉은 자세·걸친 겉옷·기계 몸)은 **기준 이미지**에 대한 경고로 유지. 요청 문장의 자세(앉기 등)는 자유 생성에서는 허용(모델이 못 하면 결과 검사·판정으로 걸러짐).
- 처음 측정 전까지 통과율 목표를 정하지 않는다(D-118 운영 규칙: 판정 20건마다 반복 실패만 공통 규칙 수정).

## 6. 첫 측정(요청 20, 승인 뒤 작성)
- 기준 이미지: 편집 성공 사례 3명(예: N3·S04·N1 중 합성·판정 통과 결과). 요청 3종: (a) 문장 없음(무작위 자세) (b) 자세 문장 1개 (c) 배경 문장 1개 → 6장 안팎(판정 시트 4~6줄 원칙).
- 잠글 기준: 자동 특징 검증 + 사람 판정(same_character·request_followed). 수치 목표는 이 측정으로 정한다.

## 9. 실제 기록과 품질 경계 (2026-10-14 구현)

- `inputs/conditions.json`: 입력 사실과 사용자 확인/자동 분석/공통 정책 출처, 조건 포함·제외 이유. 빈 특징 태그는 확인 불가로 두고 프롬프트에서 제외한다.
- `qwen-inputs/free_spec`, `qwen[-2]/request.json`, `model_inputs/prompt.txt` 및 전처리 그림: 실제 전달한 이미지·프롬프트·SHA. 머리 참조는 동일 캔버스에서 파생되었는지 워커도 검증한다.
- 무작위 연출 선택 `selection_seed`는 실행마다 한 번 뽑고 저장한다(재현하려면 호출자가 지정, 요청 20은 42). 생성 seed 42와 재시도 생성 seed 43에서도 프롬프트·머리 참조·요청 조건은 바꾸지 않는다.
- `trace.json`: 설정·운영 코드·계약 SHA, 모델 설정/명세 SHA, 모든 시도의 worker 기록(메모리·시간 포함), 결과 좌표 분할과 특징별 관찰, fulfilled/violated/unmeasurable/not_reviewed 판정, 주체·대상 시도/이미지 SHA·근거. Qwen 실패도 요청과 중단 이유를 보존한다.
- `outcome.json`: 검토 대기 또는 사용 차단. 자동 `quality_pass`는 항상 null. `judgement.json`은 실제 사람 확인 때만 쓰고 trace와 같은 이미지 SHA에 연결한다. 편집용 합성 기반 quality_pass와 혼용하지 않는다.
- 원본 기준 성공은 자유 생성에서 원본 의상이 유지됐다는 관찰이지 의상 교체 문제 해결 증거가 아니다. 의상 편집 기준을 낮추거나 편집 실패를 숨기지 않는다.
- 출력 색·태그는 자동 관찰이고 개수·연결·의상 세부·동일성·연출 반영은 미검토 또는 확인 불가다. 모델의 생성 원인은 실행 관찰과 별도의 가설로만 설명한다.

- 비어 있는 요청의 기본 자세만 전신으로 정한다. 명시적 구도·시점 요청을 공통 전신 강제로 덮어쓰지 않는다. 다중 인물 요청은 기존 제품 제외 범위를 유지한다.

## 10. 1차 완료 기준 (2026-10-16 사용자 "권고대로", D-133)

자유 생성의 목적은 둘이다 — (1) 이미지 생성 AI로서의 그림 품질(사용자가 보여 준 예시 수준의 완성도: 배경·선·마무리, 예시는 기준점이지 입력이 아님), (2) 나중에 사람·LLM이 프롬프트를 써서 붙일 수 있는 호환성.

**A. 품질 — 고정 평가 세트 1회, 사용자 판정**
- 세트: 성인 캐릭터 약 5명(기존 N1·N2·K + 처음 보는 2명), 배경 있는 장면 위주 연출 4종, 약 20줄. 승인된 의상 편집본이 있으면 그것을 기준으로.
- 줄마다: 같은 캐릭터·의상 유지·연출 반영·심한 이상 없음(팔다리 개수 포함)·**완성도(good/lacking)**. 모두 통과면 품질 통과.
- 두 수치를 따로 잰다: **1장 통과율**(첫 시도만)과 **선택 통과율**(만든 후보 중 하나라도 통과). 완료 = 선택 통과율 70% 이상, 같은 실패 유형이 2명 이상에서 반복되지 않음, 처음 보는 캐릭터에도 통과 줄 있음.
- 범위: 지원 자세 목록(standing·sitting_stool·kneeling_one_knee·walking·arms_crossed)과 일반 장면. 목록 밖 요청은 완료 판정 대상이 아니다.

**B. 호환성 — `docs/FREE_GENERATION_API.md`**: 입력·요청 문장 규칙, 고정 거부 코드(`FreeGenerationRejected.code`), 결과 형식 `free_generation_outcome/2`(D-137에서 /1 → /2), GUI 없이 부르는 시험. API 서버·LLM 연결은 만들지 않는다(D-110).

**C. 끝내는 규칙**: A가 모자라면 공통 개선은 최대 2번, 같은 세트로 다시 잰다. 남는 실패 유형은 '지원 범위 밖' 경고로 돌리고 운영 모드(판정 20건마다 공통 규칙 수정, D-118과 같은 방식)로 넘어간다. 그림체 반영(4단계)·구조 결함 자동 검출(5단계)은 다음 단계.

## 11. 운영 규칙 — 생성 조합 고정 (2026-10-19, D-140)

새 그림마다 낱말·문턱·캐릭터별 규칙을 고치던 반복을 끊는다(사용자 검토 요청 "반복적인 수동 조정 줄이기").

1. **생성 조합 고정**: D-140 시점의 지시문·설정(D-139 없는 부위 부정 지시문 포함)이 기준 조합이다. 새 그림이 실패해도 지시문 낱말·문턱·캐릭터별 규칙을 고치지 않고 실패만 기록한다.
2. **생성 쪽 변경 조건**(셋 다): ① 캐릭터 하나에 맞춘 것이 아닌 공통 변경, ② 같은 실패 분류가 운영 판정에서 **2명 이상** 반복, ③ 미리 정한 기준으로 **한 요인만 바꾼** GPU 확인(요청 28 방식) 통과. 못 미치면 버린다.
3. **판정·보정 쪽 변경**(검출 문턱·자동 보정 채택 조건)은 저장된 결과와 사람 판정으로 **오프라인 채점 먼저**(D-137 방식). 악화 1건이면 연결하지 않는다.
4. **새 그림 절차**: 입력 확인(성인·성별·귀·꼬리·날개 예/아니오) → 고정 조합 생성 → 자동 판별(고정 실패 분류표, `genai_lab/free_generation_metrics.TAXONOMY`) → 검증된 자동 보정만(지금은 한 가지 색 계열 머리색, D-137) → 사람 선택·승인 → 20건마다 집계(`scripts/free_generation_metrics.py`).
5. **특징 선택 단계**(`genai_lab/feature_selection.py`): 특징마다 조건/관찰/요청 때문에 제외로 나누고 이미지 근거 충돌을 `trace.input_facts.feature_selection.warnings`에 남긴다. 지시문은 바꾸지 않는다(1번). 검증 기준에서는 지우지 않는다.
6. 반복되지 않은 실패는 사용자 안내 경고로만 남기고 **판정 결과를 바꾸지 않는다**(실패를 사후에 '지원 범위 밖'으로 돌려 통과 처리하지 않는다).
