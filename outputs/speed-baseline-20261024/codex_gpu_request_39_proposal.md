# GPU 시험 요청 39 (제안) — 40단계 블록 오프로드 설정 측정, 최소 범위 (승인 전 — 구현도 승인 뒤)

## 요약

- **상태: 제안.** 측정용 코드 변경과 GPU 실행 모두 사용자 승인 뒤다. 요청 38(세션)과 섞지 않는다 — 요청 38 결과가 나온 뒤 따로.
- **질문:** 40단계 동안 변환기 블록을 옮기는 방식을 바꾸면 단계 시간이 줄어드는가. 그때 장치 전체 GPU·프로세스 GPU(전용·공유)·PyTorch 예약 최고·RAM은 얼마인가. 그림은 같은가.
- 근거(요청 37 기록): 40단계가 행의 76~83%, 단계당 42~48초. 지금 설정은 블록 1개씩, 옮기기와 계산을 겹치지 않음(`use_stream` 없음). 그 동안 PyTorch reserved는 2.35~2.64GiB였다.
  - **이 값만으로 GPU 여유를 정하지 않는다**: 장치에는 CUDA 문맥·다른 프로그램·드라이버 몫이 있고, Windows는 그래픽 메모리가 모자라면 시스템 RAM(공유 GPU 메모리)으로 넘겨 느려질 수 있다. 그래서 세 가지를 함께 잰다.

## 설정 후보 (한 번에 하나, 제품 기본값 아님)

| 이름 | 바꾸는 것 | 예상되는 대가 |
|---|---|---|
| 기준 | 지금 그대로(`num_blocks_per_group=1`, 겹치기 없음) | — 요청 37 A3가 기준 |
| S1 | 겹치기만: `use_stream=True`(다음 블록을 미리 옮김) | GPU에 블록 2개분, 고정(pinned) RAM 증가 가능 |
| S2 | 한 번에 2블록: `num_blocks_per_group=2`(겹치기 없음) | GPU에 블록 2개분 |

- 두 후보 모두 계산 자체는 같아야 한다 → **raw SHA가 요청 37 A3와 같아야 통과**. 다르면 요청 38과 같은 방식으로 '불일치 — 원인 조사'(자동 판정 없음).
- 결과가 좋아도 바로 제품 기본값으로 쓰지 않는다. 채택은 사용자 결정.

## 필요한 코드 변경 (승인 뒤, CPU 시험 포함)

- 설정 검사가 `group_block1` 말고는 거부한다(`qwen_pose_settings`) → **시험 전용 이름**(`group_block1_stream`, `group_block2`)을 측정 실행에서만 받게 한다. 제품 설정 파일·기본값은 그대로.
- 작업 프로세스가 고른 설정을 기록에 남긴다(`offload`). 측정 실행기는 요청 38의 메모리 표본기(장치·프로세스별·RAM)를 그대로 쓴다.

## 측정 (승인 뒤)

- 줄: **A3 한 줄**(재시도 없음 → 작업 프로세스 1회, 40단계 1번). 입력·장면 seed·생성 seed 42는 요청 37과 같다.
- 실행: 기준은 다시 돌리지 않고 요청 37 A3 기록을 쓴다(같은 그림·같은 시간 기록). S1·S2 각 1회. 예상 각 약 40분.
- 기록: 단계 시간(평균·범위), 생성 전체, 장치 전체 GPU 최고, 프로세스 전용·공유 GPU 최고, PyTorch reserved 최고(단계별), RAM 최고, raw SHA.
- 중단: reserved > 6.5GiB → 그 설정 실패(상한 완화 없음). 공유 GPU 메모리가 크게 늘면 기록하고 그 설정은 채택 후보에서 뺀다.

## 하지 않는 것

- Python·패키지 변경, 단계 수·해상도·재시도 변경, 세션(요청 38)과 같은 실행에 섞기.
