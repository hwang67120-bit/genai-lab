# GPU 시험 요청 21 — D-126 관찰·참조·지시문 개선의 요청 20 대비 비교 (초안, 실행 승인 전)

요청 20(원본 N1·N2·K, 6줄)과 **같은 입력·같은 요청·같은 seed**로 다시 생성해, D-126 변경 묶음이 결과와 자동 관찰을 낫게 했는지 본다. 생성 코드는 D-126 구현(eda61999) 이후 HEAD로 잠근다. 상태: **초안 — 사용자 실행 승인 전에는 GPU를 쓰지 않는다.**

## 결론부터(비교 목적)

1. **생성 결과**: 얼굴 기준 머리 참조(③)·'다색 태그 제외 + 색 배치 유지' 문장(②)·고유 형태 메모(④)로 요청 20에서 깨진 특징이 유지되는지. N2-2 원색 머리 추가, N1 하트 꼬리 끝, K-1 오드아이가 핵심.
2. **자동 관찰**: 새 규칙(①②⑤)이 **처음 보는 결과**에서도 맞는지. 문턱은 요청 20의 10시도로 정했으므로(맞춰 쓰기 위험), 이번 결과가 첫 일반화 확인이다.
3. 이 비교는 **변경 묶음 전체**의 효과다. 크롭·문장·메모 중 무엇이 원인인지 나누는 A/B가 아니다(K는 크롭이 그대로라 K의 차이는 크롭 때문이 아니다).

## 고정 조건과 사전 검사

- 공통 `run_free_generation`, Qwen-Image-Edit-2511, 요청 20과 같은 로컬 모델·워커·설정(40단계, CFG 4.0, guidance 1.0, group_block1). 설치·다운로드·RAG·학습·머리 합성 없음.
- selection_seed 42, 생성 seed 42, 제품 자동 재시도만 43 한 번. 재시도는 이제 **확신 있는 위반(`retry`)과 안전 차단만**이다(D-126 ⑤).
- 실행 전후 SHA 잠금: 이미지·프롬프트·설정·모델 명세·코드·계약·특징표(고유 형태 메모 포함). 실행 코드 = 승인 시점 HEAD(eda61999 이후, 이 문서 커밋 포함).
- **배치 중 코드 변경 금지**: Claude는 `codex-preflight-21/batch-status.json`이 running이면 genai_lab 코드를 수정·커밋하지 않는다(요청 20 충돌 재발 방지).
- 사전 CPU 확인: 새 참조 크롭이 요청 20 재판정 값과 같은지 — N1 [313,17,518,287], N2 [304,33,463,278], K [335,51,523,268], 셋 다 scope head. 지시문에 `multicolored_hair`·`streaked_hair` 등이 없고 "Keep the exact hair colors…" 문장과 영어 메모 문장이 있는지 실제 `qwen/request.json`으로 대조.
- GPU 작업 순차: 기준 분할 종료 → Qwen 종료 → 결과 분할. 원본 마스크를 결과에 대지 않는다.

## 판정 기준과 기록

- 실행 completed와 사용자 품질 승인은 따로 센다. 새 목표 통과율을 만들지 않는다.
- **비교 그림(작게, 기준별 한 장 = 2줄)**: 원본 | 새 머리 참조 | 요청 20 최종 | 요청 21 seed42 | 요청 21 재시도(있으면). 줄마다 사람이 기록:
  - 기본 항목: 같은 캐릭터 yes/no, 의상 same/partial/different, request_followed yes/partial/no, 부위 kept/changed/missing/added, 심한 이상 none/present+내용, 고유 형태 메모마다 유지 yes/no.
  - 요청 20 대비: 캐릭터·의상·요청 반영 각각 나아짐/같음/나빠짐.
- **자동 관찰 맞음 여부**(이번 결과에서): 재시도 근거(`retry_items`)가 사람 관찰과 맞았나, 사람이 본 변화를 자동이 놓쳤나, 의상 태그 차이(`garment_tags`)가 실제 의상 변화와 맞았나. 틀린 재시도·놓침을 숨기지 않는다.
- 두 시도가 생기면 사람이 고른 시도를 기록한다(`target.attempt`). 자동 순서를 품질 순서로 쓰지 않는다.
- 보존: `trace.json`, `inputs/conditions.json`(request_conflicts·distinctive_review 포함), `qwen[-2]/request.json`, 실제 모델 입력, run.json 최고 reserved·시간, 결과 분할·특징 관찰, 사용자 judgement.json.

## 예상 시간·메모리와 종료

요청 20 실측: 한 시도 Qwen 약 30~33분, 분석 포함 한 줄 약 34분(재시도 있으면 약 67분), Qwen 최고 reserved 6.33GiB, 분할 최고 5.08GiB. 재시도가 줄면 약 3.5시간, 모두 재시도하면 약 7시간. 6.5GiB 상한·VAE 타일·lm_head CPU 유지. 공유 GPU 작업과 겹치면 시작 보류. 계약 불일치·메모리 초과·모델 실패는 즉시 보고하고 자동 재실행하지 않는다. 시험 도중 조건 조정·추가 seed 없음.

## 결과별 다음 결정

- 요청 20보다 나아지고 퇴보 없음: 승인 사례 보존. 다음은 처음 보는 캐릭터 몇 명(평가 ④ 보류 해제 여부)이나 승인 편집본 기준 시험 중 사용자 결정.
- 생성 결과는 그대로인데 자동 관찰만 나아짐: 관찰 개선은 유지, 생성 쪽(참조·지시문) 다른 설계 검토. 캐릭터별 예외는 넣지 않는다.
- K-6에서 메모 때문에 눈을 뜸: 요청과 충돌하는 메모를 지시문에서 빼는 공통 규칙(예: 눈 감기 요청이면 눈 색 메모 제외)을 설계 제안.
- 자동 관찰 오판이 새로 나옴: 이번 결과까지 합쳐 문턱을 다시 보고, 같은 자료로 맞춘 위험을 적어 둔다.
