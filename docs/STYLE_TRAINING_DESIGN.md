## 결론

**추천: 자료 준비 필요.** 지금은 학습을 시작하지 않는다.

- **막는 것:** 학습에 쓸 수 있는 허가 그림체 자료가 **0장**이다(2절).
- **된 것:** 학습한 LoRA를 우리 추론(GGUF Q4_K_M, 6.5GiB 상한)에 얹는 기술은 요청 35·36에서 확인했다.
  - 720곳에 경고 없이 적용됐다.
  - 생성 중에 얹을 때 추가 비용은 작업 프로세스 시간 +4~23초(평균 약 +11초), 메모리 reserved +0~0.004GiB였다(8단계).
- **배울 것:** 핵심 4항목(빛의 방향, 입체적인 명암, 머리카락 표현, 의상 재질)을 바꾸면서 보호 특징은 유지하는 것(1절).
  - 보호 특징에는 이번에 깨진 드레드락, 머리 배색, 피부톤, 발광 눈이 들어간다.
- **방식:** 생성 한 번에 적용하는 경로(② 자세·장면 단계에 LoRA)를 우선한다(4절).
- **다음 할 일:** 자료 준비 경로를 사용자가 고르고, 자료 요건표(2-3)를 채운다. 자료가 채워지기 전에는 내려받기·학습·GPU를 하지 않는다.

## 1. 무엇을 배울 것인가

### 1-1. 바꿀 것 (핵심 4항목, STYLE_STAGE_DESIGN 5-1)

| 항목 | 학습 목표 |
|---|---|
| 빛의 방향 | 광원 방향이 읽히고 얼굴·몸·옷에 일관되게 반영 |
| 입체적인 명암 | 얼굴·머리카락·옷의 형태가 그림자·밝기 차이로 드러남 |
| 머리카락 표현 | 머릿결·덩어리·광택 구분 — **기본 배색은 그대로** |
| 의상 재질 | 천·가죽·금속에 맞는 주름·반사 — **디자인은 그대로** |

- 우선 목표는 참고 4번(단순 배경에서도 완성도가 드러나는 명암·머릿결·옷 주름과 재질)이다.
- 기록만 하는 4항목(피부 표현, 색채 구성, 선과 세부 묘사, 빛 효과와 배경)은 일부러 학습 목표로 삼지 않는다.
- 요청 36의 LoRA는 평평한 셀 채색으로 가는 쪽이었다. 이 학습은 반대로 **입체 명암 쪽**이다.

### 1-2. 유지할 것 (보호 특징 — 이번에 깨진 것을 명시)

| 보호 특징 | 이번 실패 예 | 학습이 지켜야 할 것 |
|---|---|---|
| 머리 형태 | A1 드레드락 → 곧은 머리 | 드레드락·땋은 머리·곱슬 등 **머리 형태 종류**는 그대로, 표현(명암·광택)만 |
| 머리 배색 | A3 분홍빛 소실, N1 머리색 위반(요청 35) | 기본색·배색 위치·옅은 색조(분홍빛 등) 유지 |
| 피부톤 | A1 전체가 밝아짐 | 어두운 피부톤 포함 **고유 피부톤** 유지. 국소 조명 변화만 허용 |
| 눈 | A3 발광 흰 눈 → 파란 눈동자, K 오드아이 소실(요청 35) | 홍채 없는 눈·발광 눈·오드아이 같은 **비표준 눈**을 표준 눈으로 바꾸지 않음 |
| 그 밖 | — | 얼굴 식별 특징, 의상 디자인, 장식·귀·꼬리 개수, 체형·자세·구도(5-1 동일성 표) |

**왜 깨졌다고 보는가(가설, 학습 설계의 근거):**
- 그림체 LoRA는 학습 그림에 **자주 나온 특징**도 함께 배운다. 학습 그림이 대부분 밝은 피부·곧은 머리·보통 눈이면, 그림체와 함께 이것들도 '정답'으로 끌어당긴다.
- 그래서 **보호 특징이 다양하게 들어간 자료**가 필요하다. 드레드락·어두운 피부·발광 눈을 목표 그림체로 그린 그림이 학습에 있어야 '그림체는 바꾸고 이 특징은 그대로'를 배울 수 있다.
- 이 가설은 빌린 LoRA의 학습 자료가 공개되지 않아 확인할 수 없다. 학습 후 평가(3절)에서 확인한다.

### 2-2. 학습 방식에 따라 필요한 자료가 다르다

같은 캐릭터를 두 그림체로 그린 짝 자료가 반드시 필요하다고 가정하지 않는다. 방식마다 근거와 함께 정리한다.

| 방식 | 학습 입력 | 필요한 허가 자료 | 근거 | 확인할 것 |
|---|---|---|---|---|
| ① 목표 그림만(짝 없음) | 목표 그림체 그림 + 설명 문장 | 목표 그림체 그림만 | 일반 그림 생성 모델의 그림체 LoRA는 보통 이렇게 학습한다 | 편집 모델(2511)을 짝 없이 학습할 수 있는지 **확인 안 됨**. 학습 도구 문서는 편집 학습을 '조절 그림(입력)'과 함께 설명한다(musubi-tuner) |
| ② 역방향 짝 만들기 | 입력 = 허가 그림을 **우리 모델로 다시 그린 AI 화풍판**, 목표 = 허가 그림 원본 | 목표 그림체 그림만(짝은 우리가 만듦) | 편집 학습 구조(입력 → 목표)를 그대로 쓰면서, 짝마다 같은 캐릭터라 **'특징은 그대로, 그림체만'**을 직접 가르친다. 1-2의 보호 특징 문제에 가장 직접적 | 허가 조건이 '우리 모델로 변형본 만들기'를 허용하는지. 입력 생성에 GPU 시간 필요(장당 약 5~30분) |
| ③ 같은 캐릭터 두 그림체 짝 | 입력 = 원래 그림체, 목표 = 같은 캐릭터를 목표 그림체로 | 같은 캐릭터를 두 그림체로 그린 짝 | 가장 직접적이지만 | 짝 자료를 구하기 가장 어렵다(의뢰 비용 두 배) |

- **권장 순서:** ②를 1순위로 설계한다. ①은 학습 도구가 짝 없는 편집 학습을 지원하는지 확인되면 대안이 된다. ③은 비용 때문에 마지막이다.
- ②는 어떤 방식이든 '허가된 목표 그림체 그림'이 출발점이라, **자료 준비가 먼저**인 것은 같다.

## 3. 일반화를 어떻게 확인할 것인가

- **캐릭터 분리:** 학습 자료와 평가 캐릭터를 완전히 나눈다.
  - 평가 캐릭터는 지금까지의 평가 세트(N1·N2·K·M2·M3·M6·M7·F5)와 요청 34 캐릭터(A1·A3·B2)다.
  - 평가 캐릭터와 그 출처 그림은 학습에 넣지 않는다.
  - 학습 자료 쪽에도 캐릭터별 묶음을 두고, 학습 때 일부 캐릭터를 빼 둔 검증 묶음을 따로 둔다.
- **이번에 깨진 특징을 평가 항목에 고정:**

| 평가 줄 | 확인할 보호 특징 |
|---|---|
| A1 | 드레드락 형태, 어두운 피부톤 |
| A3 | 발광 눈(홍채 없음), 흰 머리의 분홍빛 |
| K | 오드아이, 흑백 배색 |
| N1 | 회색 계열 다색 머리, 꼬리·날개 개수 |
| M7·B2 | 일반 특징(대조) |

- **판정:** STYLE_STAGE_DESIGN 5-1 그대로다.
  - 핵심 4항목: 개선 / 변화 없음 / 악화 / 판단 불가
  - 보호 특징: 유지 / 위반 / 가림·측정 불가
  - 사람 판정이 기준이다. 자동 검사 '위반 없음'은 통과가 아니다(M7 0.6 선례).
- **암기를 성공으로 보지 않는 장치:**
  - 학습 그림을 그대로 넣어 잘 나오는 것은 성공 근거로 세지 않는다. 평가는 학습에 없는 캐릭터에서만 한다.
  - 결과가 학습 그림의 구도·캐릭터를 닮아 가는지(섞임)를 따로 판정한다. 2줄 이상이면 그 강도는 중단한다(5절 기존 중단 조건).
  - 학습 그림과 결과의 이미지 유사도 상위 몇 장을 나란히 보여 주는 확인표를 만든다(판정 보조, 자동 통과 아님).
- **비교 기준:** 같은 입력·장면·seed에서 LoRA 없음과 LoRA 있음을 같은 크기로 비교한다(요청 36 방식).

## 4. 제품 속도를 어떻게 지킬 것인가

| 경로 | 추가 시간 | 추가 메모리 | 근거 | 판단 |
|---|---|---|---|---|
| **생성 한 번에 적용**(② 자세·장면 단계에 LoRA를 얹음) | 장당 +4~23초(평균 약 +11초) | reserved +0~0.004GiB(최고 6.375) | 요청 35 실측(8단계, 작업 프로세스 시간, 8칸) | **우선 경로** |
| 별도 후처리 한 번(결과 그림을 다시 변환) | 장당 **약 27~30분** | 최고 6.145GiB(별도 실행) | 요청 36 실측(40단계) | 부담 큼. 생성 한 번 경로가 실패할 때만 다시 검토 |

- 40단계 생성에 LoRA를 얹을 때의 추가 시간은 아직 실측하지 않았다. 8단계 결과로 보면 비율상 작을 것으로 본다(추정).
- ②에는 원래 그림체의 기준 그림·머리 크롭이 함께 들어간다. 그래서 LoRA가 그림체를 끌고 가는 힘과 원래 그림체로 돌아가려는 힘이 부딪힌다(STYLE_STAGE_DESIGN 2절).
  - 요청 35에서 차이가 안 보인 것이 이 때문인지는 가리지 못했다.
  - 2-2의 방식 ②(입력 = AI 화풍판, 목표 = 허가 그림)는 '입력 그림을 보면서 그림체만 바꾸는 것'을 직접 배우므로, 이 충돌에 맞는 학습 구조로 본다(가설).

### 5-2. 중단 기준 (미리 고정)

1. 2-3 자료 요건표를 허가 증빙과 함께 채우지 못하면 학습을 시작하지 않는다.
2. 허가 조건이 학습이나 변형본 생성(방식 ②)을 허용하지 않으면 그 자료는 뺀다. 남은 자료로 요건표를 못 채우면 1번과 같다.
3. 학습 도구가 우리 방식(②, 또는 ①)으로 2511 편집 LoRA를 만들지 못하면, 시범 학습 1회 뒤 중단하고 원인을 보고한다.
4. 평가(3절)에서 학습에 없는 캐릭터의 보호 특징 위반이 이번 실패 특징(드레드락·피부톤·발광 눈·머리 배색·오드아이) 중 하나라도 2줄 이상에서 나오면 그 LoRA는 채택하지 않는다.
5. 핵심 4항목 중 개선이 하나도 없거나, 배경·채도만 바뀌면 채택하지 않는다.
6. 섞임(학습 캐릭터를 닮아 감)이 2줄 이상이면 그 강도는 중단한다.
7. 어떤 경우에도 강도·seed·다른 LoRA 탐색으로 자동 확대하지 않고 원인과 채택 여부를 보고한다.
8. 메모리 상한 6.5GiB는 추론에서 완화하지 않는다.
