# 머리 재생성 메모리 비교 시험 (2026-10-10)

결론: 기존 방식은 예약 메모리 한도로 중단됐지만, 블록 오프로드와 효율적인 UNet attention을 함께 쓴 시험은 두 seed 모두 완료됐다. 머리 품질은 아직 판정하지 않았다.

| 방식 | 결과 | 실제 사용량 최고 | 예약량 최고 | 이미지 생성 시간 |
|---|---|---|---|---|
| 전체 모델 오프로드 | 첫 UNet 뒤 중단, 0장 | 6.055 GiB | 6.520 GiB | 완료 시간 비교 불가 |
| 블록 오프로드 + 효율적 attention | 2/2 완료 | memory.jsonl 참조 | 4.666 GiB | 99.75초 / 91.92초 |

## 확인한 원인과 범위

기존 방식의 실패 시점에는 다른 모델의 GPU 가중치가 0바이트였고 UNet 가중치만 5,982,425,096바이트(약 5.57 GiB)였다. 모델들이 동시에 남아 있는 문제는 아니었다. 계산 중 최고 실제 사용량은 6.055 GiB였지만 예약량은 6.520 GiB였으며, 계약은 예약량 6.5 GiB이므로 그대로 중단했다. 예약량과 실제 사용량의 차이만으로 메모리 누수나 단편화를 확정하지 않는다.

대안은 기존 제품의 finishing_offload와 finishing_memory를 시험 실행기에서 재사용했다. UNet 블록 1개씩 이동, 스트림 없음, 얼굴 참조 가중치를 소속 블록과 함께 이동, 효율적 attention 전용이다. 스케치 어댑터는 잔차 계산 뒤 CPU로 내렸다. 두 최적화를 함께 적용했으므로 각각의 기여도는 분리하지 않았다. 다른 attention 커널의 수치 차이가 있을 수 있어 이전 생성 결과와 픽셀 동일성을 주장하지 않는다.

해상도 1024×1024, sketch 0.8, 얼굴 참조 0.9, 28단계, CFG, prompt, negative, seed, 입력과 6.5 GiB 한도는 유지했다. 운영 코드·GUI·기본값은 수정하지 않았다. 실패 폴더는 보존했고 자동 재시도나 조건 완화는 하지 않았다.

## 검사

- 기존 메모리 기능 CPU 테스트: 16개 통과.
- 실행기 CPU 검사: 28단계 복원, 마지막 노이즈 제거, 얼굴 보호 및 영역 밖 픽셀 검사 통과.
- 각 seed: UNet 28회(CFG batch 2), 복원 콜백 28회, 스케치 어댑터 1회.
- 얼굴 참조 층의 실제 실행 횟수 및 GPU 장치 검사 통과, UNet 실행 뒤 가중치 CPU 이동 검사 통과.
- 최종 합성: 눈·코·입과 편집 영역 밖 픽셀 원본과 동일.
- 시험 종료 뒤 모든 입력 SHA를 다시 대조해 일치 확인.
- 부위 분할 별도 프로세스 최고 예약량 5.078 GiB, fp32 VAE 인코딩 3.367 GiB. 생성 모델과 동시에 실행하지 않음.
