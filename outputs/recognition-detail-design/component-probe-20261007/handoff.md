# 꼬리 조각 보존 진단 검토와 Claude 인수인계
날짜: 2026-10-07. 운영 미반영, 코드 작성 Linux, CPU 실행 Windows.

## 결론
S06의 실제로 보이는 칼날 말단이 가장 큰 조각만 사용하는 계산에서 제외된다는 점을 재확인했다.
모든 유지 조각의 뼈대 끝점을 수집하자 칼날 말단이 후보에 포함됐다.
다만 S06 후보는 24개다. 최종 말단을 고르는 기능은 구현하지 않았으며 가려진 연결이나 3D 형태를 알아낸 것이 아니다.

## 실행
- 기준: criteria.md, 실행 전 SHA는 protocol_lock.json. 원본/마스크 SHA는 run/*.json.
- 입력: outputs/tail-complexity-claude-verify-20261006/replay/original의 저장된 마스크 6장.
- 원본 SHA·상자·해상도·마스크 픽셀 수를 기존 comparison.json과 확인.
- T1b와 6장 모두 마스크 픽셀 수 동일. T1b의 원시 mask.png는 저장되지 않아 T1b 바이트 동일 검증은 불가.
- Windows 명령: D:/genai-cache/venv/Scripts/python.exe -B <이 폴더>/run_probe.py
- 모델 추론 0회, 이미지 생성 0회, GPU 0회, 다운로드·설치 없음.
- CPU 합성 테스트 6개 통과. 입력 마스크 불변, 두 조각, 한 조각, 잘못 향한 조각, 분기, 고리, 고립점 확인.
- 전체 22.63초(UNC 파일 읽기·해시 포함), 개별 사례 계산/읽기/시트 0.36~0.88초, 프로세스 최대 RAM 0.107 GiB.
- 추적된 소스/설정/문서와 T1b 기록 등 보호 파일 436개 해시 비교: 변경 0개.
- docs/BACKLOG.md, docs/ROADMAP.md는 시작 전부터 수정 상태. approved-bases/, inputs/training_candidates/도 미추적 상태 그대로이며 건드리지 않음.

## 에이전트 육안 검토
- run/S06.png: 작은 청록 칼날 조각의 위쪽 끝(기존 정답 상자)이 새 파란 끝점 후보로 포함된다.
- 큰 조각의 장갑판/톱니 외곽도 뼈대 가지와 끝점이 된다. 작은 조각 유지와 물체 말단 판별은 별도 문제다.
- 주황 점선 2개는 기하 조건을 통과한 선이다. 하나는 다리 뒤 연결과 시각적으로 맞아 보이지만, 다른 후보도 남아 있다. 정답 연결 라벨이 없으므로 성공/실패 판정하지 않는다.
- run/S03.png: 현재 청록 정답 상자는 화살촉의 아래쪽에 있고, 화면 위쪽의 뾰족한 끝 후보는 상자 밖이다. 기존 라벨의 '끝'이 말단 점인지 끝 장식 영역인지 재확인이 필요하다. 기존 상자와 점수는 수정하지 않았다.
- 마스크 자체가 정확한지, 누락된 아주 작은 조각이 없는지는 이번 보존 시험의 독립 정답 평가가 아니다.

## 추천 다음 처리
1. 운영 반영은 아직 하지 않는다. 기존 중심선은 복잡도·무늬 지표에도 쓰이므로 바로 교체하면 잠근 v3 측정값이 바뀔 수 있다.
2. 후속 설계에서는 '각 조각의 끝점 후보'와 '선택한 물체 말단'을 분리한다.
3. 기하 연결 후보에 붙일 가림 물체 근거와 복수 후보 처리, 가려진 진짜 끝의 보류 기준을 따로 정의한다.
4. S06은 설계 자료로만 사용하고, 실제 연결 검증에는 별도 중간 가림/말단 가림/관계없는 끈 사례가 필요하다.
5. S03 라벨 의도 확인 전에는 이번 후보 포함 수로 합격 결론을 내리지 않는다.
6. 기존 24개 색 견본의 사용자 판정은 여전히 별도 대기이며 대신 판정하지 않았다.
