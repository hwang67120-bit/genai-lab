## 목표와 범위

S01·S02를 기준으로 단일 그림체를 학습하고, 캐릭터 동일성을 유지하면서 빛·명암·재질 표현이 좋아지는지 확인한다. 클라우드에서 검증한 가중치를 로컬에 저장하고 설치형 앱에서도 검증한다.

사용자가 RunPod에 약 $20를 준비했다고 밝혔다. 이번 작성에서는 잔액과 현재 요금을 조회하지 않았다. 사용자가 다른 GPU 전용 채팅에 직접 인계한다. 문서 작성은 다운로드·추가 생성·유료 자원 생성·학습 실행 승인이 아니다.

메모리 최적화보다 학습·품질 검증을 먼저 진행한다. 로컬 속도·메모리 검증은 학습 결과 선정 뒤에 수행한다.

## 기존 설계와 이번 결정

기존 STYLE_TRAINING_DESIGN.md와 STYLE_STAGE_DESIGN.md는 이전 시험과 보호 특징의 근거로 유지한다. 이번 사용자 결정은 사람이 그린 자료 수집에서 **조건을 확인한 모델로 직접 생성한 합성 이미지 선별**로 자료 준비 경로를 바꾼 것이다. 기존 업체 문의·사람이 그린 자료만 수집하는 경로를 이번 작업의 선행 조건으로 적용하지 않는다.

생성 모델의 라이선스·출력 이용 조건을 출처 기록에 남긴다. AI 생성이라는 이유만으로 모든 이용 조건이 해결됐다고 기록하지 않는다.

## 자료 준비

**기준 2장 → 후보 생성 → 선별 → 부족한 구성 보충 → 학습 자료 확정** 순서다.

- 우선 총 10장을 목표로 한다. 10장은 성공을 보장하는 최소 수량이 아니라 첫 시험 규모다.
- 후보 10장 중 6장만 적합하면 나머지를 보충한다. 기존 두 장도 결함 검수를 거쳐 포함한다.
- 복제·크롭으로 수량만 채우지 않는다.
- 그림체는 유지하면서 성별·피부색·머리 형태·의상·자세·배경을 분산한다. 여성은 밝고 부드럽게, 남성은 어둡고 단단하게만 표현되는 편향을 피한다.
- 손·얼굴·관절·의상 구조 결함, 원치 않는 장식, 글자·워터마크, 다른 그림체는 제외하거나 보류한다.
- 캡션은 실제 이미지 내용을 적는다. 생성 지시와 결과가 다르면 지시문을 정답으로 복사하지 않는다.
- 이미지별 모델 ID·리비전·설정·seed·SHA·캡션·선택 근거·사용자 판정을 연결한다.

산출물: 개별 PNG·TXT, 비교표 PNG, 자료 목록, 채택·보류·제외 기록. 원본은 보존한다.

## 학습 전에 확정할 사항

학습 대상은 앱이 사용하는 Qwen 편집 모델이다. 자료 생성 모델과 혼동하지 않는다.

1. Qwen-Image-Edit-2511과 학습 도구의 지원 범위.
2. 완성 이미지·캡션만 필요한지, 내용이 대응하는 변환 전후 이미지가 필요한지.
3. 학습 기반 가중치·정밀도·VRAM·저장 공간. 추론용 GGUF Q4를 그대로 학습할 수 있다고 가정하지 않는다.
4. LoRA 적용 모듈·파일 형식·로컬 로더 호환성.
5. 해상도·배치·rank·학습률·반복 횟수·저장 및 검증 간격·최대 실행 시간.

설정은 실행 채팅에서 도구와 모델 문서를 확인한 뒤 고정한다. 지금 추정값으로 채우지 않는다.

## 실행 계획

| 단계 | 작업 | 완료 조건 |
|---|---|---|
| 자료 준비 | 후보 생성·선별 | 일관성과 다양성을 갖춘 자료 목록 확정 |
| 설계 | 학습 방식·도구·설정 고정 | 로컬 적용 경로와 비용 산정 가능 |
| 평가 고정 | 학습에 없는 캐릭터·장면 선정 | 비교 조건과 판정표 고정 |
| 예비 실행 | 로딩·짧은 학습·저장·재로딩 | 실측 시간·메모리로 예산 내 완료 가능 |
| 첫 학습 | 설정 한 벌, 중간 가중치 보존 | 예산 내 완료 또는 중단점 도달 |
| 클라우드 비교 | LoRA 없음과 학습 결과 비교 | 동일성·스타일·품질·연출 각각 판정 |
| 로컬 확인 | 회수한 가중치를 앱에서 적용 | 결과·시간·메모리 확인 |

비교 입력·참조·장면 문장·seed·해상도·생성 단계를 고정한다. LoRA와 트리거가 함께 바뀌면 명시하고 LoRA 단독 효과로 단정하지 않는다.

클라우드와 로컬의 양자화·정밀도·장치가 다를 수 있으므로 픽셀 SHA 일치를 자동 통과 조건으로 삼지 않는다. 조건 차이를 기록하고 시각 품질과 보호 특징을 평가한다.

실행 성공과 제품 채택을 구분한다. 그림체가 개선돼도 중대한 동일성 손실이 있으면 기본값으로 채택하지 않는다. 소규모 결과로 일반 성공률을 주장하지 않는다.

## 예산과 중단 기준

아래는 요금 견적이 아닌 총 $20 지출 상한 배분안이다. 후보 생성에 클라우드를 쓰면 그 비용도 포함한다.

| 용도 | 상한 |
|---|---:|
| 환경 준비·예비 실행 | $3 |
| 첫 학습 | $10 |
| 비교 생성 | $5 |
| 저장·회수 등 예비비 | $2 |
| 합계 | $20 |

- 실행 직전 GPU 요금·저장 비용·잔액을 확인한다. 다운로드·설치 대기 과금도 포함한다.
- 예상 비용은 준비 + 실측 속도로 계산한 학습 + 검증 + 저장·회수 비용이다.
- 예비 실행에서 초과가 예상되면 본 학습을 시작하지 않는다. 비용 상한·알림 기능을 확인하고 실행 시간 제한을 둔다.
- 메모리 초과, 비정상 손실 값, 저장·재로딩 실패, 자료 형식 불일치 시 중단한다.
- 동일성이 크게 깨지거나 스타일 효과가 없으면 자동 반복 학습하지 않는다. 원인과 다음 변경 하나를 정리한다.
- 추가 지출은 남은 예산과 판단 근거를 확인한 뒤 결정한다.

## 회수와 설치형 앱 검증

회수 대상: LoRA·중간 체크포인트, 기반 모델 ID·리비전, 설정·환경 버전, 자료 목록·SHA·캡션, 로그·실제 지출, 비교 이미지·판정.

로컬 저장본 크기·SHA·읽기 가능 여부를 확인한다. 회수 전에 유일한 클라우드 사본을 삭제하지 않는다. 회수 후 GPU 인스턴스와 남은 유료 저장 자원을 확인하여 불필요한 과금을 종료한다.

설치형 앱 적용은 로컬 검증 후 별도 단계다. 기존 기준 빌드·제품 기본값은 변경하지 않는다. 학습 가중치 적용 이후 속도·메모리를 다시 측정한다.
