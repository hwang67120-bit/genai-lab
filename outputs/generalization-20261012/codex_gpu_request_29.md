# GPU 시험 요청 29 — 고정 생성 조합의 운영 기준선 측정 (초안 2026-10-20)

D-140으로 생성 조합을 고정했다(`docs/FREE_GENERATION_CONTRACT.md` 11절). 같은 평가 세트 21줄(`eval-set-26/proposed-inputs.json`)을 **제품 기본값 그대로** 한 번 재서 운영 기준선으로 삼는다. 완료 기준 재판정이 아니다(완료 기준 C의 공통 개선 기회는 끝남). 요청 27의 판정·통과 줄 수는 바꾸지 않는다. 상태: **초안 — 사용자 승인 전**. 실행: **Codex**. 실행 코드: D-140 커밋(`640a2171`) 이후 HEAD.

## 요청 27 대비 바뀐 것(제품 기본값, 이것만)

1. 없는 부위 문장 → 부정 지시문 칸(D-139/140). 21줄 모두에 적용. **부위가 일부 있는 N1(꼬리·날개)·N2(귀·꼬리)는 GPU로 처음 확인**한다 — N1 부정 지시문 `animal ears`, N2 `wings`.
2. 머리색 자동 보정(D-137): 대상이면 `hair_auto` 후보가 생기고 먼저 보인다(원 결과 보존).
3. 특징 선택 단계(D-140): 경고만 기록, 지시문 변화 없음.
- 그 밖(입력·특징표·장면·seed 42/43·재시도 규칙·설정·모델)은 요청 27과 같다.

## 시작 전(램 교체 당일)

1. 사용자: 전원 끄고 플러그 뽑기 → `B538380E`(채널 A) 빼고 새 32GB 장착, `C826380F`(16GB) 유지 → 켜고 `mdsched.exe` 1회.
2. Claude: 모델 33개 SHA 대조(일반 읽기 + 디스크 직접 읽기), CPU 전체 시험.
3. Codex 사전 검사: 줄마다 요청 27 지시문과의 차이가 위 1번(없는 부위 문장 제거)뿐인지, 부정 지시문 값이 줄의 부위와 맞는지 대조. 입력·설정·모델 SHA 잠금.

## 실행

- 요청 27 실행기 구조(이어서 실행 가능, 거부·실패는 기록하고 다음 줄). 상태 파일 이름은 요청 26·27처럼 `batch-status.json`으로 맞추기를 권함(Claude 감시가 그 이름을 본다 — 요청 28은 `status.json`이었다).
- 시간: 요청 27 실측 시도당 약 41분 × 약 30시도 ≈ 18~21시간(새 램으로 모델 불러오기가 짧아지면 덜). 배치 중 Claude는 커밋하지 않고 상태 파일을 열지 않는다.
- 모델 SHA 불일치·작업 프로세스 비정상 종료는 그 줄에서 멈추고 보고, 자동 재실행 금지.

## 판정과 집계

- 판정 묶음: 원본 | 요청 29 후보 | 요청 27 같은 줄(참고), 한 장 4~6짝. **판정 이유는 고정 실패 분류표**(`free_generation_metrics.TAXONOMY`: hair_color·hair_style·head_accessory·eye_color·skin·outfit_part·extra_body_part·pose·framing·structure)로 기록.
