# 참조 이미지 일관성 실패와 승인 Anchor 전환 기록

> 이 문서는 문제 해결 기록이며 활성 제품 계약이 아니다. 현재 목표와 실행 흐름은 docs/FLOW.md를 따른다.

## 문서 목적

이 문서는 여러 참조 이미지에서 한 명의 캐릭터를 일관되게 생성하려던 과정에서 발생한 문제, 실제로 확인한 결과, 폐기한 가설과 다음 개발 기준을 기록한다.

생성 결과에 대한 사용자 평가는 수치와 구분해 적는다. 한 장의 성공이나 실패를 다른 입력에도 적용되는 일반적인 성능으로 확대하지 않는다.

기록 기간: 2026-09-16~2026-09-19

현재 상태:

- 참조 이미지 기반 일관성 생성이라는 목표는 유지한다.
- 최초 후보를 자동으로 정답으로 취급하지 않는다.
- 사용자가 확인한 편집 결과를 `승인 Anchor` 후보로 사용한다.
- 명백한 손상만 반환을 차단하고, 유사도 차이는 미세조정 대상으로 기록한다.
- 캐릭터, 동물귀·꼬리, 의상과 그림체 자료는 역할별로 분리한다.
- 미세조정과 자세 제어의 실제 효과는 아직 측정하지 않았다.

## 처음부터 유지된 목표

입력은 다음과 같이 서로 다른 역할을 가진다.

- 기준 캐릭터 이미지: 얼굴, 헤어, 성별, 동물귀, 꼬리와 캐릭터 정체성
- 의상 이미지: 의상 종류, 색상, 재봉 구조와 장식
- 자세 이미지: 필요한 경우에만 사용하는 공간 배치와 관절 정보

목표는 이 입력을 근거로 한 명의 캐릭터를 생성하면서, 참조에 없는 성별·의상·동물 종·색상으로 바뀌는 현상을 줄이는 것이다. 단순히 오류 없이 이미지를 한 장 만드는 것은 성공 기준이 아니다.

## 정확한 용어

| 용어 | 이 프로젝트에서의 뜻 | 혼동하지 않을 내용 |
| --- | --- | --- |
| Text-to-Image, T2I | 텍스트와 조건을 받아 노이즈에서 새 이미지를 생성하는 방식 | 원본 픽셀을 그대로 복사하는 과정이 아니다 |
| Base 후보 | 후속 편집 전에 생성된 첫 캐릭터 후보 | 자동으로 올바른 기준 이미지가 되는 것은 아니다 |
| 승인 Anchor | 사용자가 얼굴·헤어·동물귀·꼬리·성별·구조를 확인해 후속 단계의 기준으로 선택한 이미지 | 모델 가중치 또는 학습 결과가 아니다 |
| Conditioning | 프롬프트, 이미지 임베딩, ControlNet 지도처럼 생성 방향을 제시하는 조건 | 결과를 픽셀 단위로 보장하는 계약이 아니다 |
| IP-Adapter | 참조 이미지 특징을 교차 주의 계층에 전달하는 어댑터 | 의상 재봉 구조나 원본 좌표를 그대로 복사하지 않는다 |
| Image-to-Image, I2I | 입력 이미지를 시작점으로 다시 노이즈를 더하고 복원하는 생성 방식 | 낮은 `strength`도 모든 세부 보존을 보장하지 않는다 |
| Inpainting | 마스크로 지정한 영역을 중심으로 다시 생성하는 방식 | 마스크 안에 원하는 구조를 그릴 능력을 새로 만들지는 않는다 |
| 네이티브 다중모드 편집 | 이미지와 지시문을 모델이 함께 해석해 전체 결과를 다시 만드는 편집 | 로컬 마스크 합성이나 hard paste와 같은 방식이 아니다 |
| Seed | 초기 확률 표본을 재현하기 위한 난수 시작값 | 같은 Seed라도 모델·설정·입력이 다르면 같은 결과가 아니다 |
| 추론 | 고정된 모델 가중치로 결과를 계산하는 실행 | 여러 번 실행한다고 모델이 학습되는 것은 아니다 |
| 미세조정 | 학습 이미지로 모델 또는 어댑터 가중치를 갱신하는 과정 | 후보를 여러 번 생성하는 과정과 다르다 |
| Hard safety gate | 손상, 고신뢰 성별 충돌과 명백한 구조 붕괴처럼 반환을 막는 검사 | 미세한 유사도 차이를 판정하는 점수가 아니다 |
| 품질 진단 | 얼굴·헤어·의상·색상 등의 차이를 다음 수정 대상으로 기록하는 검사 | 보정되지 않은 CLIP 값을 성공 확률로 해석하지 않는다 |
| 합성 | 서로 다른 결과의 픽셀이나 crop을 붙여 최종 이미지를 만드는 과정 | 현재 승인 Anchor 중심 경로에서는 사용하지 않는다 |

## 문제 해결 과정

### 1. 프롬프트 전달과 태그를 먼저 의심했다

초기 결과에서는 사용자가 지정하지 않은 성별, 바지, 다른 동물귀와 다른 색상의 꼬리가 나타났다. 처음에는 다음 원인을 의심했다.

- 성별 태그가 실제 생성 프롬프트까지 전달되지 않음
- 토큰 제한으로 중요한 단어가 잘림
- `ear`, `tail`처럼 한 단어가 여러 시각적 의미를 가짐
- 텍스트 조건과 IP-Adapter 시각 조건이 서로 충돌함

남성 Base 프롬프트에 `1boy, male focus, masculine silhouette`를 추가했다. 2026-09-16 GPU 로그에서는 Positive 74/77토큰, Negative 75/77토큰으로 잘림이 없었다. 후보 3과 4는 남성 판정을 통과했다.

이 결과로 확인한 범위는 다음과 같다.

- 해당 실행에서 성별 프롬프트는 실제 모델 호출까지 전달됐다.
- 성별 조건 강화는 일부 후보의 성별 유지에 효과가 있었다.
- 프롬프트 전달 성공만으로 캐릭터·의상·구조 일관성이 해결되지는 않았다.

### 2. 잘못된 결과를 막기 위해 계약과 게이트를 강화했다

성별, 동물귀 종, 이미지 무결성, 공간 구조와 유사도를 각각 검사했다. 반환 경로가 늘면서 의미 폴백과 유사도 폴백에도 동일한 구조 검사를 적용하려고 했다.

이 단계에서 다음 구현 결함을 확인했다.

- 기본 후보 3·4가 성별을 통과했지만 후보 5·6 성별 재시도가 열렸다.
- 초기 재시도 판단이 전체 후보 결과가 아니라 일부 폴백 목록만 확인했다.
- 유사도 폴백 경로에서 `candidate_structure_gate`가 누락됐다.
- 모든 유사도 항목이 기준 미만인데도 가장 높은 실패 후보를 반환하는 경로가 있었다.
- GUI 실행과 별도 시험 실행이 한동안 같은 승인·게이트 경로를 사용하지 않았다.

게이트를 고친 뒤에는 잘못된 결과 반환이 줄었지만, 정상에 가까운 후보도 포함해 모든 후보가 폐기되는 `gate lockout`이 반복됐다.

확인 로그 예:

- `logs/20260916-195355.log`: 모든 후보가 의미 또는 유사도 게이트에 실패
- `logs/20260917-164541.log`: 모든 보정 후보가 최종 게이트에 실패
- `logs/20260918-150633.log`: `no_safe_retry_available`
- `logs/20260918-154356.log`: `quality_retry_exhausted`
- `logs/20260918-195729.log`: 모든 후보가 필수 품질 게이트에서 격리
- `logs/20260918-205729.log`: 유사도 부족 후보 3개와 손상 후보 1개 뒤 실행 실패

여기서 확인한 사실은 게이트가 결과를 분류하거나 차단할 수는 있어도, 틀린 동물귀·꼬리·의상 구조를 올바르게 다시 생성해 주지는 않는다는 점이다.

### 3. 출력 좌표 마스크와 픽셀 보존을 적용했다

참조 이미지 분석 마스크를 무작위 Base T2I 좌표에 직접 사용하지 않고, 생성된 후보에서 의상·동물귀·꼬리·헤어 좌표를 다시 검출했다. 얼굴과 사람 형태의 귀는 얼굴 보호 영역에 포함했고, 동물귀와 헤어 장식은 별도 보호 대상으로 구분했다.

2026-09-18 실제 입력 시험에서는 hard mask 외부 픽셀을 원본으로 복원했다.

- 캐릭터 입력: `HFTK9dCbgAAkxKb.png`, 936×2048픽셀
- 의상 입력: `19f3058071f8221e4d563036a40a03b5.jpg`, 736×1308픽셀
- GPU: NVIDIA GeForce RTX 4060, 8188MiB
- SDXL Inpaint 실행: 790.958초, 외부 변경 0픽셀
- Animagine XL 실행: 122.338초, 외부 변경 0픽셀

두 실행 모두 마스크 외부 보존에는 성공했지만, 마스크 내부에서 정확한 치마 구조를 만들지 못했다. 원시 후보부터 보디슈트가 남거나 골반과 치마가 비대칭이었다.

따라서 다음 두 결과를 분리했다.

- 픽셀 보존 성공: 마스크 밖의 변경을 차단함
- 의미 생성 실패: 마스크 안에 필요한 의상 구조를 만들지 못함

마스크 정확도와 생성 모델의 표현 능력을 같은 문제로 취급하면 안 된다는 근거다.

### 4. 네이티브 편집 결과에서 다른 경로의 가능성을 확인했다

두 참조 이미지를 함께 읽는 네이티브 다중모드 편집 후보 한 장은 다음 특징을 보였다.

- 출력: 848×1855픽셀
- 한 명의 캐릭터
- 짙은 청록색 블레이저
- 분리된 주름 미니스커트
- 바지 없음
- 파란 동물귀와 줄무늬 꼬리
- 흰 배경
- 사용자 평가: 거의 성공

이 실행에서는 자동 성별·구조·유사도 게이트와 원본 외부 픽셀 동일성 검사를 실행하지 않았다. 표본도 1장이므로 일반적인 성공률은 확인할 수 없다. 사용 모델과 재현 가능한 로컬 실행 식별자도 저장소 증거만으로는 확정할 수 없다.

확인할 수 있는 의미는 제한적이다.

- 목표 조합을 표현할 수 없는 문제로 단정할 수는 없다.
- 로컬 Base 후보를 계속 보정하는 경로보다 전체 참조를 함께 해석한 편집 결과가 해당 한 장에서는 목표에 가까웠다.
- 이 결과를 다음 생성의 기준으로 삼으려면 먼저 사용자가 승인하고 실행 조건과 이미지 해시를 기록해야 한다.

### 5. 로컬 네이티브 편집 모델도 자동 해결책은 아니었다

Qwen-Image-Edit-2509를 RTX 4060 8GB에서 로컬로 실행했다.

- 입력: 동일 승인 Base, 격리된 의상 보드, Seed 1767824957
- 해상도: 320×512픽셀
- 추론 단계: 20
- 추론 시간: 1,820.05초
- 전체 시간: 1,900.64초
- 실행 상태: 완료

실행은 완료됐지만 얼굴, 헤어, 동물귀, 꼬리, 자세와 전신 구도를 보존하지 못했다. 의상 보드의 몸통을 확대된 편집 대상으로 생성했으므로 제품 계약에는 실패했다.

이 결과로 네이티브 다중모드 구조라는 이름만으로 일관성이 보장되지 않으며, 모델별 입력 형식과 학습 분포를 실제 입력으로 검증해야 한다는 점을 확인했다.

### 6. Base와 승인 Anchor의 역할을 다시 정의했다

초기 Base 생성기는 정상적으로 이미지를 반환할 수 있었다. 문제는 그 결과가 참조 캐릭터의 얼굴·헤어·동물귀·꼬리·의상을 충분히 보존하지 못했는데도 후속 단계의 기준으로 고정됐다는 점이다.

후속 편집이 앞 단계의 이미지를 다시 입력으로 사용하면 그 이미지의 구조가 다음 결과에도 강하게 남는다. 잘못된 하의나 작은 캐릭터, 분리 객체가 포함된 Base를 계속 입력하면 후속 결과가 그 오류를 더 선명하게 표현할 수 있다.

이 현상은 다음처럼 기록한다.

- `잘못된 Base 학습`: 부정확한 표현이다. 추론 중 모델 가중치는 바뀌지 않는다.
- `Anchor 편향`: 앞 단계 이미지가 후속 생성의 강한 시작 조건으로 작용한다.
- `반복 편집 드리프트`: 이전 출력을 다시 입력할 때 원본 참조에서 점차 멀어지는 현상이다.
- `오류 강화`: 기존 오류가 다음 단계의 조건으로 전달되어 더 명확해지는 관찰을 뜻한다. 별도 학습이 일어났다는 뜻은 아니다.

독립된 Seed 후보를 여러 장 생성해 좋은 결과를 선택하는 경우에는 횟수가 늘었다고 각 이미지의 품질이 자동으로 향상되는 것이 아니다. 좋은 결과를 발견할 기회가 늘어나는 선택 효과와, 이전 출력을 다시 입력하는 반복 편집을 구분해야 한다.

## 원인 분류

### 직접 확인한 원인

- 프롬프트 전달 성공과 이미지 일관성 성공은 서로 다른 결과였다.
- 일부 반환 경로에 구조 게이트가 빠졌고 재시도 조건도 전체 후보를 보지 않았다.
- 강한 게이트는 잘못된 결과를 막았지만 결과가 한 장도 나오지 않는 잠금을 만들었다.
- 마스크 외부 0픽셀 변경을 달성해도 마스크 내부 의상 의미는 실패할 수 있었다.
- GUI와 별도 실행기가 다른 경로를 사용하면 같은 시험으로 비교할 수 없었다.
- Qwen 로컬 편집은 실행에 성공했지만 해당 입력의 일관성 계약에는 실패했다.

### 현재 증거가 지지하는 해석

- 참조 정보를 충분히 보존하지 못한 Base를 후속 기준으로 사용한 것이 반복 오염의 주요 증폭 요인이었다.
- 프롬프트·IP-Adapter 조건만으로 얼굴, 헤어, 동물귀, 꼬리와 의상 재봉 구조를 동시에 고정하기에는 입력 표현이 부족했다.
- 사후 게이트를 추가하는 방식은 생성 능력의 부족을 해결하지 못했다.
- 거의 성공한 편집 결과를 승인 Anchor로 고정하고 작은 변화만 허용하는 편이 현재 입력 한 쌍에서는 더 유망하다.

### 아직 일반화할 수 없는 내용

- 승인 Anchor 방식이 다른 캐릭터와 의상에서도 같은 품질을 내는지
- 반복 편집 횟수와 참조 유사도의 정량적 관계
- FLUX.2 Klein과 OmniGen의 실제 로컬 비교 결과
- 캐릭터 LoRA가 동물귀·꼬리·헤어를 자유 자세에서도 유지하는지
- 의상 LoRA를 분리했을 때 캐릭터 LoRA와 충돌하지 않는지
- 강화학습 또는 선호도 학습이 필요한지

## 폐기하거나 수정한 가설

| 가설 | 판정 | 근거 |
| --- | --- | --- |
| 중요한 성별 프롬프트가 잘려서 실패했다 | 해당 GPU 실행에서는 기각 | 74/77, 75/77토큰으로 전달됐고 남성 후보가 생성됨 |
| 게이트를 더 추가하면 원하는 이미지가 생성된다 | 기각 | 반환 차단은 늘었지만 올바른 의상 생성은 개선되지 않음 |
| 외부 픽셀 오염이 의상 실패의 주원인이다 | 해당 국소 시험에서는 기각 | 외부 변경 0픽셀에서도 내부 의상 구조가 실패함 |
| 실행이 느리면 모델이 더 정확하게 추론한다 | 기각 | Qwen은 1,820.05초 추론 후에도 일관성 계약에 실패함 |
| 생성 횟수가 늘면 모델이 스스로 학습한다 | 기각 | 추론은 가중치를 갱신하지 않음 |
| 네이티브 다중모드 모델이면 일관성이 자동 해결된다 | 기각 | Qwen 실제 입력 시험이 실패함 |
| 한 번의 거의 성공한 결과로 전체 방법이 검증됐다 | 보류 | 표본 1장이고 자동 점수·다른 입력 검증이 없음 |

## 제어권을 적용할 위치

프로젝트가 복잡해진 원인은 제어 자체가 아니라 결정적인 소프트웨어 계약과 확률적인 이미지 품질을 같은 방식으로 다룬 데 있었다.

다음 항목은 강한 계약으로 유지한다.

- 입력 파일 존재 여부, 이미지 형식과 해시
- 모델·설정·Seed·프롬프트와 코드 버전 기록
- GUI·CLI·GPU 시험의 공통 `GenerationOrchestrator` 사용
- 단계 순서, 예외 유형과 결과 파일 저장
- NaN, RGB 손상, 고신뢰 성별 충돌과 명백한 구조 붕괴 차단
- 승인되지 않은 이미지를 학습 자료에 넣지 않는 규칙

다음 항목은 진단값으로 취급한다.

- 캐릭터·헤어·동물귀·꼬리·의상 유사도
- 색상 차이
- 경미한 구도와 점유율 차이
- 목표 점수 미달과 계산 불가

진단값은 후보를 숨기지 않고 GUI에 표시한다. 최종 미적 판단과 승인 Anchor 선택은 사용자가 한다.

## 현재 선택한 생성 흐름

```text
캐릭터·의상 참조 입력
→ 후보 생성 또는 네이티브 편집
→ 모든 후보와 실행 조건 공개
→ 명백한 손상만 차단
→ 사용자가 얼굴·헤어·성별·동물귀·꼬리·의상을 확인
→ 승인 Anchor와 Seed·설정·해시 고정
→ 낮은 변형 강도로 후속 후보 생성
→ 부위별 유사도와 차이를 진단값으로 표시
→ 승인된 결과만 미세조정 데이터로 이동
```

이 경로에서는 이미지 병합, crop 붙이기, hard paste와 마스크 합성을 최종 생성 수단으로 사용하지 않는다. 마스크 분석은 진단과 제한된 국소 시험에만 사용할 수 있으며, 다시 사용하려면 목적과 검증 기준을 별도로 기록한다.

## 미세조정 데이터 분리 원칙

공개 데이터셋에서 구한 서로 다른 캐릭터 이미지는 동일 캐릭터 학습 자료로 취급하지 않는다. 다음 역할을 섞지 않는다.

```text
identity_train/
  동일 캐릭터의 얼굴, 체형, 헤어 자료

animal_features/
  목표 동물귀의 종·형태·색상과 꼬리 형태·색상 자료

garment_reference/
  블레이저, 셔츠, 치마와 장식 자료

style_reference/
  선화, 채색과 명암 비교 자료

class_regularization/
  다른 캐릭터의 같은 클래스 자료

holdout_evaluation/
  학습에 사용하지 않는 최종 검증 자료
```

첫 미세조정은 동일 캐릭터 정체성과 고유한 동물 특징을 작은 범위에서 검증한다. 의상과 자세는 동시에 학습하지 않는다. 강화학습이나 Diffusion-DPO는 승인·거절 쌍과 반복 가능한 평가셋이 쌓이기 전에는 시작하지 않는다.

## 다음 실험의 최소 조건

1. 거의 성공한 편집 결과를 사용자가 승인할지 먼저 결정한다.
2. 승인하면 원본 파일, SHA-256, 편집 모델, Seed, 입력 순서와 프롬프트를 기록한다.
3. 같은 Anchor에서 설정 하나만 바꾼 후보를 만든다.
4. 독립 생성과 이전 출력 재입력 결과를 구분한다.
5. 모든 후보를 숨기지 않고 동일 화면에서 비교한다.
6. 얼굴, 헤어, 동물귀, 꼬리, 의상, 성별과 구조를 항목별로 평가한다.
7. 한 방법이 두 번 연속 같은 원인으로 실패하면 새 게이트를 추가하지 않고 입력 표현 또는 모델 선택을 다시 검토한다.
8. 미세조정 전후는 학습에 사용하지 않은 고정 평가 이미지와 Seed로 비교한다.

## 개발 방식에서 남긴 교훈

- AI가 제시한 원인은 검증 전까지 가설이다.
- 컴파일과 실행 성공은 요구사항 충족의 증거가 아니다.
- 로그는 제어 장치가 아니라 실제 입력·결정·출력을 보여주는 관측 장치다.
- 한 번의 실험에서는 한 변수만 바꾼다.
- 사용자 화면과 개발 시험이 다른 경로를 사용하면 비교 결과를 확정하지 않는다.
- 생성 품질 문제를 예외 처리와 게이트 수로 해결하지 않는다.
- 성공 후보가 생기면 먼저 보존하고, 성공 조건을 기준선으로 만든다.
