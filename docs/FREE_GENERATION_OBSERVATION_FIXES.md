## 결론부터

- **승인·구현(2026-10-15)**: 사용자 "전부 권고대로 진행하고 푸쉬 해줘" — 아래 '정할 것' 네 가지 모두 권고대로. 저장된 요청 20의 10시도 CPU 재판정에서 틀린 재시도 4 → 0, 놓친 문제 2건(K-1 오드아이, N2-2 새 머리색) 검출(아래 '재판정 결과').

- 요청 20의 **재시도 4건은 모두 틀린 이유로 걸렸다**(아래 표). 진짜 문제(K-1 오드아이 소실, N2-2 원색 머리 추가)는 놓쳤다. 재시도한 결과가 더 나빠진 줄도 있다(K-2 눈 감기 약해짐, N2-2 의상 변화).
- 원인은 셋이다. ① 눈 픽셀 측정이 피부·눈꺼풀이 섞여 탁하고, 그 값이 태그를 덮어쓴다. ② 머리색은 결과의 가장 큰 색 하나만 비교해 새 색 추가를 못 본다. ③ 구체 태그가 일반 태그로 바뀌면(x_hair_ornament → hair_ornament) '바뀜'으로 센다.
- 다섯 항목 모두 공통 규칙으로 고친다(캐릭터별 예외 없음). 관찰 규칙(①·②의 비교·⑤의 재시도 조건)은 **저장된 요청 20의 10시도로 GPU 없이 다시 판정**해 확인할 수 있다. 참조 크롭(③)·프롬프트 문장(②·④)의 효과는 새 GPU 생성이 있어야 안다.
- 같은 10시도로 규칙을 정하므로 맞춰 쓰기(과적합) 위험이 있다. 다음 GPU 측정에서 처음 보는 결과로 다시 확인한다.

## ① 눈 색: 감김·가림은 확인 불가, 두 눈 따로, 태그와 엇갈리면 사람에게

- **감김·가림**: 결과 태그 `closed_eyes`·`one_eye_closed`·`covered_eyes`·`from_behind`가 0.5 이상이거나, 요청 문장이 눈 감기를 요청하면 eye_color = unknown(이유 "감김/가림"). 재시도 사유가 아니다.
- **두 눈 따로 측정**: 눈 마스크의 연결 요소 큰 것 두 개를 각각 잰다. 각 눈 안에서 채도 상위 40% 픽셀의 중앙값을 홍채 색으로 쓴다(피부·눈꺼풀 제외). 한쪽 픽셀이 모자라면 그 눈은 unknown.
- **오드아이**: 기준 두 눈의 ΔE가 25를 넘거나 heterochromia가 확정 특징이면, 결과 두 눈이 서로 문턱 안으로 같아졌을 때 changed(`heterochromia_lost`). 좌우 짝은 순서와 무관하게 가까운 쪽으로 맞춘다(시점 반전 대비).
- **우선순위**: 눈 색은 픽셀이 태그를 덮어쓰지 않는다. 태그와 픽셀이 엇갈리면 unknown("엇갈림, 사람 확인")으로 둔다. 머리·피부는 지금처럼 픽셀 우선(N4 오판 수정 근거 유지).
- 재판정 목표: K-1 → changed, K-2 #1 → unknown, N1-2 #1 → kept 또는 unknown.

## ② 다색 머리: 새 색 추가 검출, 배치 없는 다색 태그는 문장에서 빼기

- **새 색 검출**: 결과 머리 군집(k=5, 비율 0.08 이상) 하나하나를 기준 군집 전체와 비교한다. 어느 기준 군집과도 ΔE 25를 넘고 채도가 높은 군집이 있으면 hair_color = added(`new_color`, rgb, 비율). 기존 '가장 가까운 기준 군집' 비교(바뀜 판정)는 그대로 둔다.
- **태그 계층**: 결과에 기준 태그의 일반형만 있으면(기준 태그가 결과 태그로 끝남, 예: x_hair_ornament ⊃ hair_ornament) `kept_generic` → unknown("구체 형태 확인 불가"). 바뀜이 아니고 재시도 사유도 아니다.
- **프롬프트 문장**: multicolored_hair·gradient_hair·streaked_hair·two-tone_hair는 색이 어디에 있는지 말하지 않는다. N2-2 원색 추가가 이 단어 때문일 수 있다(가설, A/B 없음). 이 태그들은 특징표·검증에는 남기고 프롬프트 문장에서는 빼며, 대신 "keep the exact hair colors and their placement as in image 1; do not add new hair colors"를 넣는다. 효과는 GPU 측정으로만 확인된다.
- 문턱(25, 0.08, k=5)은 초안이다. 요청 20의 10시도와 편집 단계 저장 결과(N4 등)에서 새 오판이 없는지 확인한 뒤 확정한다.

## ③ 참조 크롭: 얼굴 기준 창, 넓으면 문장도 바꾸기

- **지금**: 머리카락 마스크 전체로 상자를 잡아 긴 양갈래가 몸까지 내려가는 N1은 [65,8,518,771](캔버스 대부분), N2도 몸·꼬리를 포함. 프롬프트는 "head close-up in image 2"라고 부른다.
- **변경**: 얼굴(face·eyes) 상자를 기준으로 창을 잡는다. 폭 = 얼굴 폭×3, 위 = 얼굴 높이×1.5, 아래 = 얼굴 높이×1.0. 뿔·귀·머리 장식은 이 창 안에 들어오면 함께 잘린다. 얼굴 마스크가 없으면 지금 방식(머리카락 상자) → 그래도 없으면 전체 캔버스, 상태를 따로 기록.
- **문장 일치**: 크롭 넓이가 캔버스의 35%를 넘으면 상태 `wide_reference`, 프롬프트는 "head close-up" 대신 "the cropped reference in image 2"로 쓴다. trace에 상자·넓이 비율·상태를 남긴다.
- 배수(3, 1.5, 1.0)는 초안이다. N1·N2·K 저장 기준으로 새 크롭 그림을 CPU로 만들어 사용자가 먼저 본 뒤 정한다. 크롭 변화가 자세·의상 유지에 주는 영향은 GPU로만 안다.

## ④ 고유 형태·의상 변화: 사람이 적는 메모 + 의상 태그 차이 관찰

- **고유 형태 메모**(특징표 새 항목 `distinctive`): 자동 추출이 못 하는 형태를 사람이 최대 4줄 적는다. 예: "heart-shaped tail tip", "right eye blue, left eye red", "X-shaped hair clip". 
  - 프롬프트에는 "keep: …" 문장으로 넣는다. Qwen 전달을 위해 **영어만 프롬프트에 넣고**, 한국어 메모는 결과 확인 창에만 보인다.
  - 입력 검사: 줄당 60자, 외형 변경 문장·노출 문장 거부(기존 검사 재사용).
  - 결과 확인 창에 메모마다 체크 줄이 생긴다("꼬리 끝 하트가 유지됐나요?"). 자동 판정은 없음(unmeasurable)으로 명시한다.
- **의상 태그 차이**: 기준·결과 태그 중 `tag_scope == "garment"`이고 0.5 이상인 것의 차이(잃음/생김)를 `garment_tags` 관찰로 기록하고 확인 창에 보여 준다(예: "shorts 없어짐, pants 생김"). 자세 변화로 가려지는 일이 많아 **재시도 사유는 아니다**. 운영 판정 20건 뒤에 사람 판정과 맞는지 보고 정한다.
- 꼬리 끝·앞치마 모양 같은 형태의 자동 측정은 이번 범위가 아니다.

## ⑤ 재시도·선택: 확신 있는 위반만 재시도, 두 결과는 사람이 고름

- **재시도 조건**: 아래만 재시도 사유다.
  - 안전 태그 차단(지금과 같음).
  - 색 changed 중 ΔE가 문턱×1.25를 넘는 것(문턱~1.25배는 unknown "경계값").
  - 태그 changed 중 바뀐 결과 태그 점수가 0.7 이상이고 일반형이 아닌 것.
  - added(새 머리색, 없던 부위).
- **요청과 충돌하는 검사 제외**: 요청이 눈 감기면 눈 색, 뒷모습이면 얼굴 항목(눈 색·피부)을 검사하지 않는다(unknown, 이유 "요청과 충돌").
- **두 시도가 있으면 사람이 고른다**: 확인 창에 두 결과를 나란히 보이고, 자동 관찰은 근거로만 붙인다. 처음 표시는 위반이 적은 쪽이며 "자동 관찰 기준, 품질 보장 아님"이라고 적는다. outcome에 `candidates`(두 시도)를 넣고, API 반환도 같은 형태. 판정 기록 `target.attempt`에 고른 시도를 남긴다.
- 운영 집계(`studio_judgement_summary.py`)에 재시도 횟수·사유를 더한다.

## 확인 방법

1. CPU 재판정 스크립트: 저장된 요청 20의 10시도 관찰을 새 규칙으로 다시 계산해 위 표와 비교한다. 목표: 틀린 재시도 4 → 0, K-1 눈·N2-2 #1 머리 추가 검출, 새 오판 없음.
2. 편집 단계 저장 결과(요청 17·18)에도 돌려 새 오판이 없는지 본다. 편집 단계는 검증이 관찰 기록일 뿐이라 재시도 규칙은 바뀌지 않는다.
3. ③의 새 크롭 그림 3장(N1·N2·K)을 사용자에게 먼저 보인다.
4. 1~3 뒤 GPU 측정(요청 21)은 사용자가 정한다.
