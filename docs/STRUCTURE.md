# 구조 설명

## 구조를 이렇게 만든 이유

처음부터 파일을 많이 나누면 실행 순서를 따라가기 어렵습니다. 그래서 기준 이미지를 먼저 `run.py` 하나로 성공시킨 뒤, 실제로 확인된 네 역할만 분리했습니다. `run.py`를 읽으면 전체 순서를 볼 수 있고 세부 동작은 역할 이름과 같은 파일에서 확인할 수 있습니다.

## 파일과 폴더의 역할

| 위치 | 역할 | 지금 필요한 이유 | 없어도 되는 시점 |
|---|---|---|---|
| `run.py` | 전체 실행 순서 | 한 파일에서 전체 흐름을 이해하기 위해 필요 | 프로젝트가 존재하는 동안 유지 |
| `gui_main.py` | Windows 화면 실행점 | 명령어 없이 캐릭터 참조 이미지를 선택하고 생성 | 명령 실행만 사용할 때 |
| `genai_lab/model.py` | 모델과 GPU 준비 | 모델을 바꿀 때 생성·저장 코드에 영향을 주지 않음 | 없음 |
| `genai_lab/style.py` | 참조 그림 준비 | 그림체 적용 여부를 다른 로직과 분리 | 참조 그림 기능을 제거할 때 |
| `genai_lab/generator.py` | 순차 이미지 생성 | 후보 3개 처리와 GPU 오류를 한곳에서 확인 | 없음 |
| `genai_lab/result.py` | 결과와 기록 저장 | 생성 코드가 파일 구조까지 책임지지 않게 함 | 없음 |
| `configs/base.yaml` | 변경 가능한 설정 | 코드를 고치지 않고 모델·크기·시드를 바꾸기 위해 필요 | 없음 |
| `configs/animagine.yaml` | Animagine XL 한 장 시험 설정 | 기존 SD 1.5 성공 설정을 유지하며 결과를 비교 | Animagine을 사용하지 않을 때 |
| `inputs/reference` | 참조 그림 | 그림체 특징을 전달할 입력 위치를 고정 | 참조 그림을 사용하지 않을 때 |
| `inputs/prompts.csv` | 후보 3개 요청 | 빠른 비교용 입력을 사람이 표로 확인 | 한 장 시험만 할 때 |
| `inputs/prompts_animagine.csv` | Animagine 시험 요청 한 개 | 후보 3장을 만들기 전에 모델 단독 동작 확인 | 단독 시험 완료 뒤 |
| `outputs` | 이미지와 기록 | 입력과 결과를 연결하고 이어서 실행 | 없음 |
| `docs` | 이유와 계획 | 구조를 이해하고 계획 없는 기능을 막음 | 없음 |
| `tests` | 자동 확인 | 구조 변경으로 기존 기능이 깨지는 것을 방지 | 없음 |
| `requirements.txt` | 설치 목록 | 다른 환경에서 같은 도구를 설치 | 없음 |

## 아직 만들지 않는 폴더

- `models`: 대용량 모델은 프로젝트 안에 복사하지 않고 `D:\genai-cache`에서 관리합니다.
- `notebooks`: 실행 경로가 둘로 나뉘므로 첫 버전에서는 사용하지 않습니다.
- `scripts`: 명령 실행은 `run.py`, 화면 실행은 `gui_main.py`가 담당하므로 별도 스크립트를 만들지 않습니다.

## 기준 생성 성공 후 적용된 분리

`run.py`의 동작을 바꾸지 않고 다음 네 역할만 분리합니다.

```text
run.py                    실행 순서
gui_main.py               Windows 화면과 백그라운드 작업 연결
genai_lab/model.py        모델 불러오기와 GPU 배치
genai_lab/style.py        참조 그림 특징 전달
genai_lab/generator.py    한 장씩 순서대로 생성
genai_lab/result.py       파일과 실행 기록 저장
```

분리 전후에 같은 설정과 시드로 생성 시험을 실행하여 동작이 유지되는지 확인합니다. 새로운 역할이 확인되지 않는 한 다섯 번째 처리 파일을 추가하지 않습니다.

현재 GUI에서 실제 사용하는 입력은 캐릭터 기준 이미지 한 장입니다. 의상과 자세는 처리 기능이 구현되지 않았으므로 화면에서 비활성화합니다.
