# GenAI Lab 개발 로드맵

## 자세 변경 제외 결정 (2026-10-09)

사용자 결정에 따라 원하는 자세로 바꾸는 기능은 이번 완성 범위에서 제외하고, 향후 외부 LLM·이미지 편집 연동 단계로 미룬다. 현재는 체형·머리카락 동일성과 생성부터 저장까지의 GUI 흐름을 우선한다.

- 기본 생성에서는 자세를 따로 지정하지 않고 기존 생성 방식에 맡긴다. 새로운 무작위 자세 생성 기능을 추가하지 않는다.
- 원본 체형과 비율을 유지하기 위한 골격·머리 윤곽 조건은 유지한다. 원본 자세를 참고하는 것과 다른 자세로 바꾸는 것은 구분한다.
- 기존 자세 코드와 시험 기록은 보존한다. 이번 결정은 코드 삭제나 생성 설정 변경이 아니며, 새 자세 GUI 연결과 추가 자세 시험은 진행하지 않는다.
- 향후 LLM이 요청을 해석하고 이미지 생성·편집 모델이 실행하는 연동을 검토한다. 자세 변경과 동일성 유지는 그때 별도로 검증하며, LLM 연결만으로 해결된다고 간주하지 않는다.

## 현재 진행 순서 (2026-10-04)

사용자 결정에 따라 **동일성 계획 종료 → 학습 → 메모리 최적화 → 배포 호환성 → 연동 호환성** 순서로 진행한다. 현재는 동일성 계획 단계이며, 뒤 단계는 예정 작업이다. 이 기록은 학습·설치·외부 API 구현을 시작했다는 뜻이 아니다.

| 순서 | 단계 | 작업과 확인할 결과 | 상태 |
|---|---|---|---|
| 1 | 동일성 계획 종료 | 캐릭터와 의상의 특징이 유지되는지 기존 계획의 결과와 미해결 항목을 정리하고 사용자 확인으로 종료한다. 자세 변경은 이번 완성 범위에서 제외하고 향후 외부 연동 단계로 미룬다. 원본 비율 유지는 계속한다. | 진행 중 |
| 2 | 학습 | 동일성 계획 결과를 바탕으로 학습 목적·대상·데이터·방법·평가 기준을 확정한 뒤 학습 전후 결과를 비교한다. 학습 방식과 수치 기준은 아직 정하지 않았다. | 동일성 계획 종료 후 |
| 3 | 메모리 최적화 | 학습이 반영된 구성에서 모델 적재·해제, RAM·VRAM 피크, 반복 생성 시 메모리 증가, 처리 시간을 측정하고 품질을 유지하며 개선한다. | 학습 단계 종료 후 |
| 4 | 배포 호환성 | 지원 환경의 다른 PC에서 설치 → 필요한 모델 준비 → 앱 실행 → 입력 선택 → 이미지 생성 → 저장까지 확인한다. | 메모리 최적화 종료 후 |
| 5 | 연동 호환성 | 다른 앱·LLM이 GUI 없이 요청을 전달하고, 진행 상태·확인 요청·결과·오류를 받을 수 있도록 연결하고 검증한다. | 배포 호환성 종료 후 |

단계 종료 여부는 해당 단계의 결과와 남은 제한을 기록해 확인한다. 학습 방법, 출시 최소 사양, 외부 연동 방식은 각 단계에서 확정한다. 이번 계획만으로 특정 학습 방식이나 API 구현을 채택하지 않는다.

## 동일성 중간 점검 (2026-10-08)

현재는 동일성 계획을 마무리하기 위한 검증·보완 단계다. 아래 수치는 기존 이미지에 대한 Claude의 잠정 판정이며, 이번 문서 갱신에서 GPU 생성이나 재판정을 한 결과가 아니다.

| 확인 대상 | 현재 근거 | 다음 작업 |
|---|---|---|
| 외형 특징 보존 | 기존 7캐릭터·28장, 부분 유지에 0.5점을 준 점수 91.5/134(68%). 고유 특징 완전 보존은 0/32, 부분 보존 8건 | 같은 기준으로 결함을 구분하고 새로운 캐릭터로 최종 평가 |
| 색 | 머리색 유효 영역 19/23(83%), 색 차이 10 이하. 부적절한 영역 5개 제외 | 머리색 외 부위를 같은 성능으로 일반화하지 않고 영역부터 검증 |
| 꼬리 | 기준선의 동일 의상 부분집합 정상 12/27(44%). 별도 의상 시험 엄격 재판정 비정상 57/110 | 서로 다른 표본을 합치지 않고, 꼬리 정리 A~D는 사용자 결정 대기로 유지 |
| 비율 | R6 1명·6 seed에서 2단계 생성 오차 중앙값 약 19% → 2.8% | 기본 OFF 내부 경로 구현 후 GPU로 기존 1단계 보존·6 seed 재현 확인 |
| 인식 | T1b 자동 말단 0/5, 수동 색 견본 사용자 판정 대기 | 인식 성공·부위 선택·색 측정을 나누어 판단 |

2단계 비율 생성은 기본 OFF로 내부 경로를 연결했다. CPU에서 스케치·흰 배경 결과 각 6/6 SHA 일치를 확인했고 GPU 재현은 대기 중이다. 머리 영역 확인은 사람이 맡고, GUI 연결은 별도 승인 전까지 진행하지 않는다. [내부 연결과 검증 순서](TWO_PASS_PROPORTION_HANDOFF.md). VRAM 6.416 GiB와 생성 시간 약 2배, 바지 아랫단 색 변형이 현재의 제약이다. 원본 자세가 다른 기준선 이미지에서는 비율을 측정하지 않았으므로 R6 시험과 구분한다.

최종 평가는 처음 보는 성인 캐릭터 8~10명으로 계획하되, [동일성 목표안](../outputs/identity-goal-roadmap-20261007.md)의 목표 수치는 아직 초안이다. 블라인드 동일 인물 판정도 아직 하지 않았다. 이 상태에서 동일성 달성이나 배포 준비 완료로 표시하지 않는다.

근거: [동일성 기준선](../outputs/identity-baseline-20261008/baseline.md), [비율 방식 결정](../outputs/head-contour-adapter-design-20261007/DECISION_proportion.md), [후속 작업·보류 항목](BACKLOG.md).

## 배포 호환성 — 사용자의 설치와 첫 생성

대상은 앱을 설치해 사용하는 사람이다. 개발 환경이 준비된 PC에서의 성공과, 처음 설치하는 PC에서의 성공을 구분한다.

- 지원 OS·GPU·드라이버·RAM·VRAM·디스크 요구량과 최소 사양을 확정한다. 기존 VRAM 8GB·RAM 16GB 목표는 최적화 검증의 출발점이며, 출시 보장 사양으로 확정된 것은 아니다.
- 패키지 버전과 모델 revision·파일 해시를 관리하고, 설치 및 모델 준비 과정을 확인한다.
- 깨끗한 지원 환경에서 설치·최초 실행·생성·저장을 검증한다. 사양 부족, 다운로드 실패, 권한 문제는 원인과 조치 방법을 사용자에게 안내한다.
- PC와 GPU가 다른 경우에는 이미지 파일 해시 일치만을 요구하지 않는다. 설치 성공, 생성 완료, 저장 성공과 사전에 정한 품질 기준으로 평가한다.
- 완료 근거는 지원 환경별 설치부터 저장까지의 기록이다. 모든 PC에서 오류가 없다고 일반화하지 않는다.

기존 환경 기록과 후속 작업은 [BACKLOG의 항목 76](BACKLOG.md)을 이어서 사용한다.

## 연동 호환성 — 외부 프로그램의 생성 요청

대상은 이 생성 기능을 사용하는 다른 앱과 LLM 연결 프로그램이다. GUI는 사람을 위한 사용 화면으로 유지하고, 외부 프로그램은 생성 기능을 호출한다.

- 요청에 포함할 캐릭터·의상 입력, 생성 옵션, 사용자 확인값과 결과 형식을 정한다.
- 작업 식별자, 진행 상태, 취소, 오류, 결과 이미지 수신 방식을 정한다. 사용자 확인이 필요한 항목은 외부 프로그램의 화면에서도 처리할 수 있게 한다.
- 외부 프로그램에서 요청 → 필요한 확인 → 생성 → 결과 수신까지 GUI 조작 없이 검증한다.
- 로컬 호출과 원격 호출의 범위, 접근 권한, 이미지가 외부로 전달되는 조건, 인터페이스 버전 호환 정책을 정한다. 외부 LLM 연동을 이미지 외부 전송에 대한 자동 동의로 취급하지 않는다.
- 완료 근거는 실제 외부 호출 사례와 실패·취소 처리 기록이다. 개발용 스크립트의 GPU 실행 성공만으로 API 호환성이 완성됐다고 기록하지 않는다.

구체적인 API·SDK·연결 프로토콜은 이 단계에서 선택한다. 현재 단계에서는 구현하지 않는다.

## 초기 계획 이력 (현재 순서를 대체하지 않음)

아래는 초기 아이콘 생성 앱 계획의 원문이다. 완료 표시·소요 시간 예상·미구현 설명은 당시 기록이며 현재 상태를 뜻하지 않는다. 현재 우선순위는 위의 5단계를 따른다.

한 단계의 완료 조건을 통과하기 전에는 다음 단계 기능을 추가하지 않습니다.

| 단계 | 작업 | 완료 조건 | 상태 |
|---|---|---|---|
| 0 | 구조와 용어 이해 | README, STRUCTURE, FLOW를 읽고 입력·처리·출력을 설명할 수 있음 | 문서 완료 |
| 1 | Windows GPU 환경 확인 | `--check-only`가 GPU와 입력 검사를 통과함 | 통과 |
| 2 | 기준 이미지 한 장 생성 | SD 1.5 512×512 PNG와 기록 생성 | 통과 |
| 2-1 | Animagine XL 한 장 비교 | 참조 그림 없이 768×768 PNG와 메모리 기록 생성 | 통과 |
| 3 | 한 장 참조 그림 적용 | 새 장면에서 참조 그림 특징이 확인됨 | 참조 그림 필요 |
| 4 | 후보 3장 순차 생성 | 3장과 각 실행 기록 생성, 중단 후 재시작 성공 | 3단계 이후 |
| 5 | 그림체 학습(LoRA) | 두 번의 3장 비교에서 매번 2장 이상 개선 | 필요할 때만 |
| 6 | 구조 안내(ControlNet) | 그림체를 유지하며 포즈·구도 개선 | 필요할 때만 |
| 7 | 최종 평가 | 후보 3장 중 최소 1장을 사용자가 채택 | 4단계 이후 |

### 2차 목표: Windows 설치형 아이콘 앱

이미지 생성 기능의 0~7단계를 통과한 뒤에만 화면과 설치 기능을 추가합니다.

| 단계 | 작업 | 완료 조건 | 상태 |
|---|---|---|---|
| 8 | 아이콘 생성 화면 | 참조 그림과 생성 내용을 입력하고 후보 3장을 한 화면에서 확인 | 7단계 이후 |
| 9 | 선택과 저장 | 후보 한 장을 선택하여 사용자가 지정한 폴더에 저장 | 8단계 이후 |
| 10 | Windows 설치형 배포 | 다른 Windows PC에서 서버 없이 설치·실행 | 9단계 이후 |

## 현재 구현 범위

현재 구현은 이미지 생성 기능에만 집중합니다. 2단계 실제 생성이 성공해 확인된 네 역할만 분리했습니다. 참조 그림과 후보 3장 생성이 안정되기 전에는 화면, 설치 프로그램 또는 배포 코드를 만들지 않습니다.

## 초고속 출시 기준

주 단위 개발이 아니라 작업시간 20~35시간, 집중 작업 시 3~5일 안에 1차 설치형 앱을 만드는 것을 목표로 합니다.

| 예상 작업시간 | 집중 작업 | 통과 조건 |
|---|---|---|
| 4~6시간 | IP-Adapter SDXL과 참조 그림 한 장 적용 | 참조 특징이 적용된 768×768 한 장 생성 |
| 3~5시간 | 후보 3장 생성과 최소 품질 조정 | 후보 3장 중 최소 한 장 채택 |
| 6~10시간 | 최소 아이콘 생성 화면 | 참조 그림 선택·내용 입력·후보 확인·한 장 선택 |
| 4~6시간 | Windows 설치형 묶음 | 서버 없이 설치하고 앱 실행 |
| 3~8시간 | 다른 PC 시험과 출시 차단 오류 수정 | 설치·모델 준비·생성·저장 전체 흐름 통과 |

### 1차 출시에 반드시 포함

- 참조 그림 한 장 선택
- 생성할 아이콘 내용 한 번 입력
- 후보 3장을 한 장씩 생성
- 후보 한 장 선택과 PNG 저장
- 한글 오류 안내
- 서버 없는 Windows 설치와 실행

### 1차 출시 이후로 미룸

- Java와 모든 백엔드 기능
- LoRA와 ControlNet 자동 적용
- 복잡한 설정 화면과 계정 기능
- 여러 작업 동시 실행과 대량 생성
- 확대, 부분 수정과 편집 기능

LoRA 또는 ControlNet은 참조 그림 시험에서 출시를 막는 품질 문제가 확인될 때만 현재 일정에 편입합니다. 속도는 검증 생략이 아니라 출시 범위 고정으로 확보합니다.

## 다음 단계로 넘어가는 규칙

1. 실행 결과를 확인합니다.
2. 완료 조건을 통과했는지 기록합니다.
3. 실패하면 현재 단계의 원인만 수정합니다.
4. 통과한 뒤 `DECISIONS.md`에 다음 기능의 필요성을 기록합니다.
5. 기록되지 않은 기능은 구현하지 않습니다.
