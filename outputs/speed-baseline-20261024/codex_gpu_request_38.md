# GPU 시험 요청 38 — 작업 프로세스 재사용(세션) 확인, 사용자 흐름 B2 한 줄 (승인 대기)

## 요약

- **상태: 승인 대기.** GPU 실행 전 사용자 승인이 필요하다.
- **질문:** 재시도(seed만 다름)에 같은 Qwen 작업 프로세스를 다시 쓰면(D-180) ① 그림이 요청 37과 SHA까지 같은가, ② 반복하던 시간(시작·모델 검사·가져오기·인코딩·불러오기)이 빠지는가, ③ 재사용 프로세스가 대기하는 동안 결과 분석(머리 분할 — 다른 GPU 프로세스)과 함께 쓰는 GPU·RAM은 얼마인가.
- **새 품질 시험·설정 탐색이 아니다.** 입력·장면 seed·생성 설정은 요청 34·37 B2와 같다. 재시도 규칙·횟수는 그대로다.
- **실행:** Codex. 코드: 이 문서를 커밋한 HEAD. 개발 환경(개발 venv + `qwen-test-venv`, 요청 34와 같은 경로) — **Python·패키지 변경 없음.** 기준 빌드(요청 37 후보)는 쓰지 않는다(읽기 전용, 예전 코드).
- 예상 시간: 요청 37 B2는 6,536초(약 109분)였다. 줄어드는 폭은 기록으로 재시도 1회의 반복분(약 217초) 안쪽으로 본다. 확정하지 않는다.

- 작업 2가 다시 쓰는 것: 불러 둔 파이프라인(GGUF 변환기·VAE·블록 오프로드), 문장 임베딩, 첫 작업의 모델 검사 기록(`files_rechecked: false`). **요청마다 새로 하는 것:** seed·생성기, 입력 그림 읽기·SHA 확인, 조건 그림(작업 1과 SHA 대조), model_inputs, 메모리 감시·상한, 단계 콜백·미리보기·진행 기록.
- 작업이 하나라도 완료되지 않으면(실패·취소·메모리 중단) 세션 프로세스는 끝나고 상태를 넘기지 않는다. 시도가 끝나면 세션을 닫는다.

2. 실행(출력 폴더는 새 폴더). 시험 프로세스 종료 코드를 따로 남긴다:

   ```
   D:\genai-cache\venv\Scripts\python.exe -X utf8 scripts\session_reuse_check.py outputs\packaging-gpu-20261023\cases-p5.json B2 D:\genai-test\session-reuse-20261024 D:\genai-test\gpu-p5-20261023\flow > D:\genai-test\session-reuse-20261024.log 2>&1; $code = $LASTEXITCODE; "실행기 종료 코드 = $code"
   ```

   - 실행기가 이 실행에서만 `GENAI_QWEN_SESSION_REUSE=1`을 켠다(제품 기본값은 꺼짐). 장면 seed는 기록값(2026898827)으로 고정.

## 보는 것 (판정이 아니라 기록 — 아래 '불일치 처리')

1. **그림:** `image_sha_comparison` — ① raw, ② 작업 1 raw, ② 작업 2 raw가 요청 37과 같은가. 저장 그림(`saved_same_as_request37`).
2. **세션 동작:** 작업 1 `files_rechecked` 참(전체 검사), 작업 2 거짓 + `text_encode_reused`·`pipeline_reused` 있음, 작업 2 `session_memory_at_start`(앞 작업 뒤 이 프로세스의 PyTorch 할당·예약), `qwen-session\job-00000N.done.json` 두 개, 시도 뒤 세션 닫힘(trace의 `qwen_session.returncode`).
3. **시간:** 작업 2의 `seconds`·`stage_seconds`, 두 작업 사이 간격, 행 전체 — 요청 37 B2(재시도 작업 프로세스 구간 2,007초, 그중 시계 전 122초·인코딩 12초·불러오기 75초·종료 8초)와 비교.
4. **메모리 — 예약량만으로 여유를 정하지 않는다:** 장치 전체 최고(`device_used_peak_gib`, 다른 프로그램 포함), 프로세스별 전용·공유 GPU 최고(Windows 카운터, CUDA 문맥 포함), **세션 대기 + 머리 분할이 함께 있던 동안의 전용 합 최고**, 프로세스별 RAM 최고. 공유(shared) GPU 메모리가 크게 잡히면(그래픽 메모리가 시스템 RAM으로 넘침) 따로 적는다.
5. **프로세스 종료:** 실행기 종료 코드와 결과를 나눠 적는다.

## 불일치 처리 (사용자 10/24)

- 그림 SHA가 하나라도 다르면 **자동으로 품질 실패나 성공으로 처리하지 않는다.** '불일치 — 원인 조사'로 적고 멈춘다.
- 조사 순서(기록만으로 먼저): 어느 raw가 다른가(작업 1·① = 새로 불러온 경로라 세션과 무관 / 작업 2만 다름 = 세션 관련 후보) → model_inputs·조건 그림 SHA, 임베딩 모양, 실제 호출 값, 단계 수 대조 → 차이 위치를 보고. 세션을 끈 대조 실행이 필요하면 **제안만** 한다(승인 전 실행하지 않음).

## 중단·기록 규칙

- `memory_stopped` 또는 PyTorch reserved > 6.5GiB → 그 줄 실패로 기록. **상한을 완화하지 않는다.**
- 재시도·대조 실행을 추가하지 않는다. seed·장면·설정·Python·패키지를 바꾸지 않는다.
- 코드를 고쳐야 할 것 같으면 고치지 말고 멈추고, 바꿀 곳과 다시 해야 할 확인을 보고한다.
- 기준 빌드 폴더·시험용 모델 폴더·공유 캐시를 지우거나 옮기지 않는다.
