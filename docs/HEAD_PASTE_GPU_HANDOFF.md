# 원본 머리 붙이기 — Claude GPU 재현 인수인계

구현과 개별 CPU 검사를 마쳤다. 제품 GPU 재현과 실제 GUI 생성은 아직 확인하지 않았다.

## 사용자 흐름

원본 비율 참고로 4장 생성 → 후보 한 장 선택 → **원본 머리 붙이기** → 원본·자동 분할·보정 영역 비교 → 맞아요/아니에요 → 붙이기와 경계 재그리기 → **별도 후보 추가** → 기존 결과와 비교 → 사용자 승인 → 저장.

기본 자동 적용은 없다. 일반 생성에서는 버튼을 숨긴다. 같은 원본 SHA·정규화·머리 마스크에서 확인 파일과 영역 파일이 변경되지 않은 경우만 확인한 영역을 기억한다. 다른 원본·윤곽이면 다시 확인한다.

원래 4장과 생성 raw는 덮어쓰지 않는다. 실패·취소·영역 거부 시 새 후보를 추가하지 않는다. 이미 머리를 붙인 후보에 다시 붙이지 않는다. 꼬리 편집 뒤 머리 붙이기는 막고, 머리 붙이기 뒤 꼬리 편집은 기존 흐름으로 가능하다. 2단계 후보의 고화질 마무리는 기존 제한을 유지한다.

## 처리 계약

| 항목 | 연결한 동작 |
|---|---|
| CPU 규칙 | H2·G3 숫자와 출처 규칙 유지, 새 좌표 변환 없음 |
| 재그리기 | 1024, index 24부터 변경 허용, 스케치 0.8·얼굴 참조 0.9·CFG 5.5·원래 seed |
| 메모리 | 분할 모델을 먼저 내리고 재그리기 모델 로드. 기존 블록 오프로드·효율적 attention, reserved 6.5 GiB 초과 시 실패 |
| 보호 | 확장 영역 밖과 눈알·코·입의 픽셀 동일 검사 |
| 실행 검사 | UNet 28회, CFG 2배치, 복원 28회, 스케치 1회 |
| 잠금 | 원본·정규화·머리 윤곽·H·raw·얼굴 참조·사용하는 모델 파일 SHA |

“마지막 4단계”는 앞 24단계 결과를 출발 잠재값으로 되돌린다는 뜻이다. 시험처럼 UNet은 28회 호출한다. 계산 자체가 4회인 것은 아니다.

원본 분할은 `hair-confirmations/<입력 해시>/<확인 ID>/original-parts.npz`, 생성 분할은 `head-pastes/<실행 ID>/generated-parts.npz`에 저장한다. 앞으로 이 자료로 CPU에서 H2와 붙이기 전체를 재계산할 수 있다.

`operation.json`: 부모가 남기는 성공·실패·취소 최종 상태. `worker-error.json`: 실패 원인. `paste-inputs.json`: 단계별 그림과 SHA. `redraw/**/run.json`: 호출·메모리·보호 검사. `result.json`: 검토 후보 연결. 실패한 중간 이미지는 보존하지만 후보로 제공하지 않는다.

## CPU 확인과 자료 부족

- 새 기능의 규칙·확인창·기억·취소·실패·후보 추가·저장·모델 없는 전달·실제 분할 도구 경로 검사: 34개 통과 (pytest-head-final.log).
- 기존 6건에서 원본 자르기 상자와 1024 원본 크롭 SHA가 동일하다. 저장된 1024 붙이기 그림·마스크·보호 영역을 제품 합성 함수에 넣었을 때 736 붙이기만 결과 SHA 6/6 일치 (pytest-reference-final.log).
- 같은 6건에서 제품 원본 입력 계약을 확인했다. GPU를 사용하지 않았다.
- **시험 당시 See-through 전체 분할 결과는 저장돼 있지 않다.** H·init·마스크 파일의 SHA를 확인한 것과 H2·G3를 처음부터 계산한 것은 다르다. CPU 전체 재계산 통과로 보고하지 않는다. 아래 GPU 실행에서 분할을 다시 저장하고 H·init·마스크·붙이기 SHA를 대조한다.
- 전체 회귀 검사 2,063개 통과, 기존 경고 2개 (343.25초, pytest-full.log). 이후 분할 도구 경로 검사 보완과 원본 자르기 검사 추가를 각각 해당 CPU 검사로 확인했다. 테스트 로그는 outputs/head-paste-product-verify-20261010/에 있다.

## Claude 실행 명령

프로젝트 폴더의 PowerShell에서 먼저 CPU 확인만 실행한다.

```powershell
& 'D:\genai-cache\venv\Scripts\python.exe' -B '\\192.168.0.109\win_g\genai-lab\scripts\verify_head_paste_product.py'
```

GPU 재현은 아래 한 줄이다. **기존 사용자 확인 H와 새 H가 같은 경우에만 기존 확인을 가져온다.** H가 다르면 자동 승인하지 않고 중단한다. 기존 실행 폴더를 덮어쓰지 않는다. 다른 GPU 작업과 동시에 실행하지 않는다.

```powershell
& 'D:\genai-cache\venv\Scripts\python.exe' -B '\\192.168.0.109\win_g\genai-lab\scripts\verify_head_paste_product.py' --run --output '\\192.168.0.109\win_g\genai-lab\outputs\head-paste-product-verify-20261010\gpu-01'
```

라쿤·근육 남성·늑대 각 seed 2개를 순서대로 실행한다. H·init·마스크·얼굴 보호·붙이기만 SHA가 다르면 즉시 중단한다. `head_1024.png`·`raw_redraw.png`는 `verify_reference.md`의 6건과 대조한다. 다르면 평균/최대 픽셀 차이·변경 픽셀 비율을 기록한다. 자동 통과시키지 않고 `needs_blind_review`로 남긴다. attention·오프로드 등 차이 원인을 조사하고 사용자 블라인드 판정 뒤 결론을 낸다.

**SHA 대조 대상은 raw_redraw다.** GUI용 product는 기존 흰 배경 제품에 같은 머리 패치만 합성해 제품의 영역 밖 픽셀을 유지한다. 제품과 raw는 서로 같은 SHA를 요구하는 값이 아니다. 각각의 보호 검사를 확인한다.

## 실제 GUI 확인

1. 원본 비율 참고 후보에서만 버튼이 나타나는지 확인한다.
2. “아니에요”를 고르면 새 후보가 생기지 않는지 확인한다.
3. “맞아요” → 완료 후 새 후보가 추가되고 원래 4장을 다시 고를 수 있는지 확인한다.
4. 같은 원본·윤곽은 확인을 기억하고 다른 원본·윤곽은 다시 묻는지 확인한다.
5. 실행 중 취소하면 원본·중간 파일·최종 취소 기록이 남는지 확인한다.
6. 새 후보는 다시 승인해야 저장되며 저장 그림과 미리보기 SHA가 같은지 확인한다.
7. 머리 붙이기 후보에서 꼬리 고치기로 이어지는지 확인한다.

CPU에서 Qt 신호는 대역으로 검사했지만 실제 모델을 사용하는 GUI 생성은 아직 아니다.

## 코드 읽기 시작점

- `studio_head_paste_gui.HeadPasteController.start`: 선택 → 입력 계약 → 영역 확인 → 후보 추가.
- `studio_head_paste.selected_request / prepare_hair / apply_head`: SHA·캐시·별도 프로세스·최종 기록.
- `head_paste_worker.prepare_preview / prepare_paste / complete_apply`: 분할 → CPU 규칙 → 재그리기 → 제품 보호 합성.
- `head_paste_rules`: H2·G3, 눈 보호·여백·수염·피부 출처.
- `head_paste_redraw.redraw_prepared`: 모델 로드 → 잠재값 계산 → 후보 재그리기 → 해제.
