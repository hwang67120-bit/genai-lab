# 머리 붙이기 회색 테두리 수정 인수인계

결론: 요청한 배경 재분리 방식은 연결했고 CPU 테스트 43개가 통과했다. 라쿤 테두리는 개선됐지만 완전히 제거되지 않았다. GPU 생성은 실행하지 않았다.

## 변경한 흐름

머리 다시 그리기가 끝난 뒤 `raw_redraw.png`를 기존 `AnimeForeground` CPU 모델에 넣어 알파를 다시 계산한다. 기존 흰 배경 합성 함수를 사용하고, 4픽셀 확장 편집 영역에서만 결과를 옮긴다. 눈알·코·입과 편집 영역 밖은 기존 미리보기 픽셀을 유지한다.

읽기 시작할 함수는 `head_paste_worker.prepare_white_product`다. 이미지 입력 → 배경 분리 → 보호 합성 → 알파 및 모델 기록 반환 순서다. 모델은 실패해도 해제한다. 모델 SHA가 다르거나 분리가 실패하면 성공 후보를 만들지 않는다.

`head_paste_rules.protected_support`는 기존 합성 허용 범위를 공유한다. `blend_result`의 원본 합성 계산은 그대로이며, 흰 배경 결과만 `blend_white_product`로 만든다. 마스크·프롬프트·다시 그리기 단계·수염 규칙·머리 범위는 변경하지 않았다.

## 검증 결과

| 검사 | 결과 |
| --- | --- |
| CPU 테스트 | 43개 통과, 58.37초 |
| 기존 6건 CPU 합성 SHA 회귀 | 6건 모두 통과 |
| 기존 GPU 결과 6건을 실제 CPU 배경 모델로 재합성 | 영역 밖·눈알·코·입 보호 모두 통과 |
| 기존 원본·붙이기·마스크·다시 그리기 파일 SHA | 6건 모두 유지 |
| 새 GPU 생성으로 원본 SHA 재현 | 미실행 |

테스트 파일: `tests/test_head_paste_product.py`, `tests/test_head_paste_rules.py`, `tests/test_studio_head_paste.py`.

5,361개 픽셀을 배경 알파 0으로 설정한 합성 회귀 시험은 모두 흰색이 된다. 이는 합성 규칙 검사이며 실제 모델이 5,361개를 모두 배경으로 판정했다는 뜻이 아니다.

### 실제 라쿤 사례

대상은 `gpu-02/be2bacf5/seed-2987514498599016057`다. 기존 배경이 모든 색 채널에서 250 이상이고, 머리 붙이기 후 달라진 픽셀을 기준으로 기존 보고의 5,361개를 재현했다.

| 항목 | 픽셀 수 |
| --- | --- |
| 기존 문제 영역 | 5,361 |
| 새 결과가 정확히 흰색(255,255,255) | 2,188 |
| 새 결과가 흰색 범위(모든 채널 250 이상) | 3,819 |
| 새 알파가 정확히 0 | 1,098 |
| 새 결과가 흰색 범위에 들지 않음 | 1,542 |

알파가 0인 곳은 모두 흰색으로 복원된다. 남은 곳은 모델이 일부 전경으로 판정했다. 이 안에는 실제 머리 경계도 있을 수 있어 전부 강제로 지우지 않았다. 동일한 모델과 합성 함수를 적용하라는 요청을 유지했고 임계값을 추가하지 않았다. 육안 확인에서도 옆머리 주변에 회색이 일부 남아 있다. 따라서 이번 결과를 완전 해결로 판정하면 안 된다.
