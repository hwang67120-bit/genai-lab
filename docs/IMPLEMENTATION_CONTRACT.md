# 구현 계약

## 2026-09-03 기준 캐릭터 교체 마스크 보강

- GUI 6/8에서 생성된 기준 캐릭터를 대상으로 교체할 기존 의상과 특수 보호 영역을 각각 선택·승인합니다. 의상 참조 이미지의 좌표를 재사용하지 않습니다.
- SAM2 위치 선택·후보 추출·후보 선택·픽셀 합집합은 기존 구현을 재사용합니다. 꼬리/귀 의미 자동 인식을 보장하지 않으며 사용자가 후보를 확인하거나 특수 보호 없음을 명시합니다.
- 승인 자료는 기준 RGB 픽셀 SHA-256과 캔버스 크기에 묶습니다. 기준이 달라지면 재승인하고, 빈 의상 또는 의상·특수 보호의 겹침은 재선택을 요청합니다.
- 이 경로에서는 승인한 의상 경계를 임의 팽창·닫기하지 않습니다. SCHP의 머리/얼굴 보호와 사용자 특수 보호를 합치되, 다리·신발을 무조건 보호하는 기존 규칙을 적용하지 않습니다. 선택하지 않은 신체/의상은 변경하지 않습니다.
- AutoMasker 원본은 진단용으로만 공개하고 실제 적용 마스크와 구별합니다. Human-Agnostic과 모델 입력 검토·승인은 그대로 유지합니다.
- 보호와 겹친 의상은 분모에서 지우지 않고 충돌로 표시합니다. 검증 대상 0px는 100%가 아니라 계산 불가이며, 이 부분은 과거 D-041/D-045의 보호 겹침 제외 규칙을 대체합니다.
- 결과의 중립색 잔여 후보는 최초 중립화 픽셀 중 결과도 같은 색 근처인 픽셀입니다. 기본 RGB 127, 채널별 허용 오차 8이며 실제 중립색을 전달합니다. 픽셀 수·비율·위치를 공개하고 벤치마크에 수치를 남기되 회색 의상을 오판하지 않도록 경고만 합니다.
- 새 모델 설치·추론 해상도·steps·CFG·strength 변경은 이 수정의 범위가 아닙니다. 결과 품질 개선은 실제 사용자 GPU 실행 후 판단합니다.
- 공식 함수 근거: [SAM2 박스 입력 및 마스크 후처리](https://huggingface.co/docs/transformers/model_doc/sam2), [OpenCV 모폴로지](https://docs.opencv.org/4.13.0/d9/d61/tutorial_py_morphological_ops.html), [Diffusers Inpaint 마스크](https://huggingface.co/docs/diffusers/api/pipelines/stable_diffusion/inpaint).

## 1. 구현 전에 전체 순서를 먼저 쓴다

코드보다 먼저 기능 실행 순서를 한 줄에 한 단계씩 작성합니다.

```text
입력 등록
→ 입력 검증
→ 데이터 가공
→ AI 모델 실행
→ 결정론적 결과 검사
→ 사용자 승인
→ 승인 결과만 저장
```

상위 함수도 같은 순서로 읽혀야 합니다.

```python
def execute_clothing_change_workflow(...) -> ClothingChangeCandidate:
    character_foreground = extract_character_foreground(...)
    existing_clothing = extract_existing_clothing(...)
    safe_change_mask = build_safe_change_mask(...)
    removal_verification = verify_original_clothing_removal(...)
    return create_clothing_change_candidate(...)
```

상위 함수에 픽셀 계산, UI 위젯 조작, 모델 다운로드와 파일 저장을 한꺼번에 넣지 않습니다.

## 2. 기존 해법을 먼저 확인한다

구현 전에 다음 7개 항목을 제시합니다.

1. 해결할 문제와 현재 실패 증거
2. 사용할 공식 라이브러리 함수
3. 검토한 프레임워크 또는 오픈소스
4. 선택한 모델·패키지의 정확한 ID와 버전
5. 라이선스와 배포 가능 범위
6. 프로젝트 실행 환경과의 호환성
7. 직접 작성해야 하는 코드와 그 이유

공식 함수나 검증된 오픈소스로 해결할 수 있으면 직접 다시 구현하지 않습니다. 후보를 사용하지 않을 때는 제외 이유를 한 문장과 확인 근거로 남깁니다.

## 3. 직접 작성할 수 있는 코드의 범위

직접 작성하는 코드는 다음 범위로 제한합니다.

- 프로젝트 데이터 모델 사이의 변환
- 라이브러리와 모델을 연결하는 얇은 실행 코드
- 입력 크기·타입·범위 검사
- 모델 출력의 수치 검증
- 사용자 승인·거절과 자동 저장 차단
- 오류 로그, 자원 해제와 실패 복구
- 프로젝트에만 존재하는 업무 규칙

다음 기능은 공식 기능이 있는데도 직접 다시 만들지 않습니다.

- 이미지 확대·축소·자르기
- 마스크 팽창·침식·열기·닫기
- 배열 논리 연산과 픽셀 집계
- 범용 이미지 형식 변환
- 모델 다운로드·캐시·추론 세션 관리
- 프레임워크가 제공하는 스케줄러·샘플러·후처리

예외적으로 직접 구현해야 하면 공식 기능을 사용할 수 없는 이유, 추가 코드 줄 수, 입력·출력과 실패 조건을 구현 전에 제시합니다.

## 4. 네 블록의 책임을 섞지 않는다

```text
사용자 입력 UI → 데이터 가공 → AI 모델 실행 → 결과 출력
```

- `gui_main.py`: 입력, 상태 표시와 사용자 승인만 담당
- `genai_lab/`: 데이터 계약, 결정론적 계산과 업무 흐름 담당
- `scripts/`: 별도 환경의 모델 실행만 담당
- `result.py`: 사용자 저장 승인 뒤 결과 기록만 담당

GUI에서 픽셀 계산이나 모델 추론을 새로 작성하지 않습니다. 모델 실행기에서 GUI 상태를 직접 변경하지 않습니다. 결과 저장 함수에서 모델을 다시 실행하지 않습니다.

2026-08-31 측정 기준 `gui_main.py`는 `4,436줄`입니다. 새 기능은 기존 GUI 연결에 필요한 최소 신호·대화상자 코드만 추가하고, 계산과 데이터 모델은 `genai_lab/`로 분리합니다. 이 수치는 품질 점수가 아니라 구조 위험을 확인하기 위한 파일 크기 기록입니다.

## 5. 이름과 객체가 데이터 단계를 드러내야 한다

- 사용자 확인 전: `Candidate`
- 사용자 확인 후: `Confirmed` 또는 `ApprovedInput`
- 검사 결과: `Verification`
- 모델 실행 결과: `ExecutionResult`
- 설정: `Settings`

이름 없는 `dict`, `list[dict]`, 단독 `result`, `data`, `value`는 업무 객체에 사용하지 않습니다. 외부 요청·응답은 Pydantic 모델, 내부 계산 결과는 dataclass 또는 이름 있는 타입으로 표현합니다.

## 6. AI 판단과 결정론적 계산을 분리한다

함수와 데이터 이름에서 다음을 구분합니다.

- AI가 추정한 마스크·좌표·태그
- NumPy·OpenCV·Pillow가 계산한 결과
- 사용자가 승인하지 않은 후보
- 사용자가 승인한 확정 입력
- 메모리에서만 사용하는 임시 값
- 파일로 저장하는 최종 값

AI 출력은 사실이나 확정값으로 이름 짓지 않습니다. AI 후보를 결정론적 검사로 통과시켜도 사용자 승인 전에는 확정값이 아닙니다.

## 11. 가드레일 승인 판정 계약

새 가드레일을 `passed: bool`로 GUI에 직접 연결하지 않습니다. 모든 검사는 공통 `GuardResult`를 만들고 중앙 `GuardDecision`이 승인 여부를 계산합니다.

```text
보정 없이 기준 통과 → PASS
보정 전 문제 발견, 자동 보정 후 최종 기준 통과 → WARNING
보정 후 최종 입력에도 문제 잔존 → BLOCK
```

수치 계약은 다음과 같습니다.

- `BLOCK=0개`이면 승인 버튼을 활성화합니다.
- `BLOCK=1개 이상`이면 승인 버튼을 비활성화합니다.
- 승인 버튼이 비활성화됐는데 `BLOCK=0개`이면 버그입니다.
- 모든 `BLOCK`에는 코드, 측정값, 기준값과 복구 행동이 있어야 합니다.
- 검사 결과가 `0개`이면 승인하지 않고 예외로 중단합니다.
- 보정 전 수치와 보정 후 최종 수치를 같은 차단 조건으로 사용하지 않습니다.
- GUI는 모든 결과의 단계·심각도·코드·측정값·기준값·보정 후 값을 표시합니다.

가드레일 추가 시 `WARNING만 있는 승인`, `BLOCK 1개가 있는 차단`, `비활성화 사유 존재` 회귀 테스트를 각각 1개 이상 추가합니다.

## 12. 생성 효과와 품질 점수 분리 계약

모델 프로세스 종료 코드 0과 보호 영역 밖 변경 0픽셀은 생성 효과의 증거가 아닙니다. 최종 승인 영역 안 변경 픽셀을 별도로 계산하며 정확히 0픽셀이면 상태를 `no_effect`로 기록합니다.

- 결정론적 픽셀 값은 즉시 실행 상태 판정에 사용할 수 있습니다.
- CLIP·DINOv2·색상 히스토그램처럼 표본 보정이 필요한 점수는 초기에는 관측값이며 GUI 승인 차단에 사용하지 않습니다.
- 품질 점수를 차단 기준으로 승격하려면 성공·실패 사용자 판정 표본이 각각 30건 이상이어야 합니다.
- 원본 좌표 승인 마스크와 모델 처리 좌표 model_mask를 같은 픽셀 수로 직접 비교하지 않습니다. 크기·좌표를 기록하고 model_mask는 최근접 보간으로 원본 좌표에 투영합니다.
- GUI는 적용 전, 원시 모델 출력, 승인 마스크, 최종 보호 합성과 차이맵을 모두 공개합니다.
- `no_effect`에서는 적용본 승인만 비활성화하며 원본 후보 선택과 창 닫기는 항상 가능해야 합니다.

## 13. 의상 생성 GUI 자동 체인 계약

전체 실행은 활성 8단계이며 의상 입력이 있으면 6/8 신체·Human-Agnostic 승인 → 7/8 2D Inpaint → 8/8 최종 승인 순서를 바꾸지 않습니다. TPS RGB 직접 합성과 Garment Lineart ControlNet은 자동 체인에서 호출하지 않고 진단·비교 자산으로만 보존합니다.

- 승인 창은 동시에 최대 1개입니다.
- 활성 Inpaint Worker는 동시에 최대 1개입니다. TPS Worker는 진단 기능에서만 실행합니다.
- Inpaint 창은 기준 캐릭터·Human-Agnostic 시작 이미지·승인 마스크·승인 의상 원본·IP-Adapter Plus 실제 참조 보드·원시 출력·보호 출력·차이맵 8개를 공개합니다.
- 자세 입력이 없거나 저장 자세 폴백을 쓰더라도 의상 좌표를 별도로 추측하지 않습니다. 포즈 적용은 기준 후보 생성 단계의 자세 ControlNet 책임입니다.
