# 요청 38 멈춤 수정 — 변경 전 재현과 변경 후 CPU 검증 (2026-10-24, D-183)

GPU를 쓰지 않았다(모든 경우 `CUDA_VISIBLE_DEVICES=-1`). 작업 프로세스는 요청 38과 같은 `qwen-test-venv` Python.

## 바꾼 것

- 세션 작업 프로세스의 부모 감시: **표준 입력 읽기 → 실행기 pid·생성 시각 확인**(2초마다). 실행기가 `--parent-pid`·`--parent-created`로 넘긴다 — `qwen-test-venv`의 Python은 중계 실행 파일 아래에서 돌아 `os.getppid()`가 실행기가 아니다.
- pid와 생성 시각이 **둘 다** 같아야 살아 있는 부모로 본다(끝난 실행기의 pid를 다른 프로세스가 받아도 오인하지 않음).
- 세션 프로세스의 표준 입력은 열지 않는다(DEVNULL).
- 시작 실패는 `session-error.json`(단계 start) + 종료 코드 2. 작업 처리 중 예외(잘못된 작업 파일·기존 결과 덮어쓰기 거부 등)는 `session-error.json` + 실패 완료 표시 + 종료 코드 1. 끝난 이유는 `session-ended.json`(close·idle·parent_gone). 실행기는 세션 프로세스가 끝나면 이 기록의 이유를 오류 안내에 붙인다.
- **그대로:** 단일 작업 경로(`run_one`·`generate`·인자 1개 실행) — 변경 전과 본문이 같다. 재사용 기본값 꺼짐.
