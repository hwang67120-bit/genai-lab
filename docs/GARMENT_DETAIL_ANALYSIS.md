# 의상 세부 분석 연결

## 실행 흐름

추출 의상 승인 → 의상 전체/확대 분석 → 의상 특징 요약 승인 → 캐릭터·프롬프트 승인 → 기존 참조 생성.

- 새 모델은 추가하지 않는다. `analyze_clothing_design`만 한 WD14 세션에서 전체/확대를 순차 분석한다. 캐릭터/눈의 `analyze_image_tags` 경로는 그대로다.
- 알파 외곽의 원본 좌표를 기록한다. 기본 전체 1회 + 긴 축의 겹치는 확대 2회. 작은 입력이나 빈 확대 창은 추가 분석하지 않는다.
- 구성품 후보, 소매/형태, 깃·여밈·장식, 소재·무늬, 스타일 맥락으로 분류한다. 이 분류는 명시적인 태그 라우팅 어휘이며 학습된 부품 검출기나 완전한 의상 사전이 아니다.
- 각 태그의 전체/확대 원점수를 따로 보존한다. 여러 뷰가 독립적이라고 가정하거나 softmax로 정확도로 바꾸지 않는다.
- 색은 알파 가중 RGB 구간 표본으로 기록한다. 투명 픽셀의 숨은 색은 제외하지만 불투명 배경, 그림자, 반사광을 의상 배색과 구별하지는 못한다.
- 전체 분석 후보는 기존 승인 경로를 유지한다. 확대에서만 발견된 구성품은 보고서에만 남기며 생성에 자동 추가하지 않는다.
- 확대 분석으로 추가된 세부 후보는 최대 12개다. 승인한 후보만 선택적 프롬프트에 넣고 필수 캐릭터·의상 조건을 먼저 예약한다. 토큰 초과 시 빠진 항목을 승인 화면 및 `omitted_detail_tags`에 기록한다.
- 성별·인물/머리 태그, 구성품/스타일 태그는 이 추가 세부 조건 통로로 전달하지 않는다. 전체 승인 조건의 `suit` 등을 일괄 삭제하거나 성별로 하의를 추가하는 규칙은 없다.
- 후보 JSON의 `garment_detail_analysis`에 뷰 좌표/시간/태그 점수/색 표본/불확실성을 저장한다. `approved_detail_tags`와 실제 토큰 생략 내역을 함께 확인한다.

## 설정과 한계

`configs/animagine.yaml → clothing_design_analysis`

- `detail_maximum_views: 3` (1~5, 1이면 전체만)
- `detail_timeout_seconds: 120` (모델 준비 포함, ONNX 호출 사이 협력적 검사; 실행 중인 호출을 강제 중단하는 프로세스 제한은 아님)

WD14 태그 점수만으로 바지/치마의 실제 겹침, 숨겨진 의상의 부재, 정확한 단추 개수, 부품별 색, 앞뒤 가림 순서를 확정하지 않는다. 확대 창은 분할 마스크가 아니다. 의상 이미지 임베딩의 성별 편향도 이번 분석 추가만으로 제거되지 않는다. 초기 RGB, 합성, 새 GPU 모델을 연결하지 않았다.

태그/승인/토큰 연결 테스트는 동작 계약을 확인할 뿐 실제 생성 품질을 증명하지 않는다. 다음 시각 테스트는 동일 입력·시드로 전체만(1뷰)과 확대 포함(3뷰)을 비교한다. 세부 태그가 실제 프롬프트에 남았는지, 겹친 의류가 감소했는지를 별도로 확인해야 한다.

## 근거 문서

[WD ViT Tagger v3 공식 모델 카드](https://huggingface.co/SmilingWolf/wd-vit-tagger-v3)는 일반 태그·캐릭터·등급 태깅 지원과 검증 지표를 설명한다. 부품 분할/가림 관계 판정 모델이라고 설명하지 않는다. 다중 확대 관찰 및 RGB 구간 요약은 이 프로젝트의 보조 분석 설계이며 공식적으로 검증된 정확도 개선으로 주장하지 않는다.
