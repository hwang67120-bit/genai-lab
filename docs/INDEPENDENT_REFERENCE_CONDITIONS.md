# 부위별 원본 조건 분리 (구조 변경만)

## 이번 적용 범위

얼굴·헤어(identity), 의상(garment), 귀·꼬리 및 기타 검출 부위를 독립적인 `ReferenceCondition`으로 보관한다. 각 객체는 RGB·원본 영향 영역의 불변 bytes, 크기, 부위 강도를 가진다. 얼굴/의상 강도는 기존 생성 설정에서 지정한다.

- `source_part_conditions`는 원본 이미지와 해당 부위 검출 결과만 받는다. 얼굴/의상 마스크를 받거나 수정하지 않는다.
- `ReferenceConditions.materialize`가 별도 조립 단계다. 원본 조건을 읽어 새로운 RGB/영향 영역 객체를 만들고 기존 배치 정책을 적용한다.
- `prepare_visual_inputs`가 실제로 이 분리 경로를 사용한다. 결과를 검토 화면, IP-Adapter 인코더, 저장 진단에서 공통 사용한다.
- 생성 전에는 독립 원본 조건에서 조립한 결과와 미리보기/실제 참조가 일치하는지 검사한다. 조건 묶음 자체의 변경도 승인 지문에 포함한다.
- `source_region_experiment.assign_source_regions`는 기존 호출자용 호환 API다. 배치 계산은 같은 순수 함수로 위임한다.

## 의도적으로 변경하지 않은 것

**최종 생성 마스크와 이미지 결과를 바꾸기 위한 수정이 아니다.**

기존 `source_roi_priority_experiment` 정책은 조립 단계에 유지했다. 따라서 귀·꼬리와 겹치는 영역은 최종 얼굴/의상 영향 마스크에서 여전히 제외되지만, 별도로 보관한 원본 조건은 잘리지 않는다. 단순히 빼기 연산을 없애서 마스크 겹침을 허용하지 않았다.

- 원본 좌표 배치와 자세 미고정 상태 유지
- 기존 검출기, 후보 선택 규칙 및 색 분석 유지
- 프롬프트·토큰 예산·사용자 지정 성별·시드·참조 강도 유지
- 공통 텍스트 프롬프트 유지 (부위별 텍스트 어텐션/별도 확산 생성 미구현)
- 새 모델, 초기 RGB, 인페인팅, 합성, 자동 생성/자동 승인 추가 없음

즉 데이터 소유권 분리는 적용했지만 확산 모델 내부의 부위 간 영향까지 차단한 것은 아니다. 같은 조건에서는 기존과 같은 입력이 전달되는 것이 이번 단계의 검증 목표다. 실제 의상/꼬리 품질 개선으로 주장하지 않는다.

## 확인 위치

입력 검토 화면에 '부위 원본 조건 분리 적용' 문구가 나온다.

후보 임시 폴더의 `independent_conditions/`:

- `identity_reference.png`, `garment_reference.png`, 부위별 참조 PNG
- `*_source_region.png`: 조립 전 원본 영향 영역
- `conditions.json`: 부위별 SHA-256, 크기, 부위 강도, 배치 정책, 전체 조건 지문

기존 `input_*_mask.png` 및 부위 폴더의 `target_region.png`는 조립 후 실제 영향 영역이다. 후보 JSON의 `reference_analysis.condition_separation`에서도 원본 조건 지문을 확인할 수 있다.

## 검증과 근거

자동 검사는 한 부위 RGB/강도 변경이 다른 원본 조건을 바꾸지 않는지, 원본/조립 결과가 별도 객체인지, 승인 후 입력 변경을 막는지, 실제 준비 경로와 인코더가 연결되는지 확인한다. 모델 품질 검증과 다르다.

[Diffusers IP-Adapter 공식 문서의 Masking](https://huggingface.co/docs/diffusers/v0.38.0/en/using-diffusers/ip_adapter#masking)은 이미지별 마스크·강도를 공통 파이프라인에 전달하는 계약을 설명한다. 이번 변경은 그 입력을 분리 관리하는 프로젝트 구조이며, 문서가 생성 요소의 완전한 독립성을 보장하는 것은 아니다.
