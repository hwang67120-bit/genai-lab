# 제품 흐름 지도 (2026-10-31, 코드 기준)

> 사용자 요청(10/31): "흐름 지도부터 만들자" — 검증(일관성·처음 보는 그림·다른 PC) 전에 실제로 도는 경로를 한 장으로.
> 근거는 코드(커밋 a57f6f82 시점)를 읽은 것이다. 실행 결과로 확인한 것과 코드만 읽은 것을 구분해 적는다.

## 0. 한 줄 결론

**사용자 화면은 Qwen 경로(모드 A)만 부른다. 목표 그림체(S4w)를 내는 FLUX 경로(모드 B)는 화면에 연결돼 있지 않다.**
그래서 지금 설치 앱을 쓰면 나오는 그림은 목표 그림체가 아니다. 두 경로가 옷 바꾸기를 각각 따로 하고(겹침), 검사 방식도 다르다.

## 1. 지금 있는 경로 세 개

## 2. 경로 A(사용자 화면) 단계

```
캐릭터 그림 (+ 의상 그림)
  └ 시작 전: 필수 모델 검사(model_check) — 없으면 멈춤
  └ 입력 분석: WD 태거(태그·안전), anime-seg(사람 영역), See-through(부위 분할), 머리 검출
  └ 성별·부위·특징표: 캐릭터 기억 → 파일 저장값 → 자동 분석 (사람 확인 없음)
  ├ [의상 있음] ① 옷 바꾸기 (outfit_edit_pipeline)
  │    옷 참조 정리(배경·머리 빼기) → 분할 → 특징표
  │    → Qwen 편집 40단계 (seed 42, 검사 실패 시 43 한 번 더)
  │    → 팔·손 검사(DWPose) → 원본 머리 붙이기 → 특징 유지 검사
  │    → 결과를 자동으로 ②의 기준으로 (사람 승인 아님, automatic_chain 기록)
  └ ② 자세·장면 (free_generation_pipeline)
       장면: 칸이 비면 자동 조합(무작위 seed), 쓰면 그 문장 / 안전 태그 검사
       → 분할·특징표 → 머리 크롭 참조(+ 자세 골격)
       → Qwen 편집 40단계 (seed 42, 위반 시 43)
       → 결과 분석(부위·특징) → 머리색 보정 후보 → 위반 적은 시도 먼저 표시
  └ 미리보기 → '저장'(사용자가 쓰겠다는 결정)
```
- 시간(화면 안내): 의상 있으면 1~2시간, 없으면 약 40분.
- 모델: Qwen-Image-Edit-2511(문장 인코더) + GGUF Q4_K_M 변환기, WD 태거 v3, anime-seg, See-through(l2d_sam), DWPose, anime_head_detection. 개발 화면 빠른 미리보기만 Lightning 가속 LoRA.

## 3. 경로 B(그림체 다시 그리기) 단계

```
캐릭터 그림 (+ 옷 그림, 선택)
  └ 캔버스 768x1024 → 관절(DWPose, 사람 1명·얼굴 확인)
  └ 준비(CPU): WD 태거 안전 검사(옷 그림도) → anime-seg·See-through → 특징 문장 → 원본 부위 마스크·손 개수
  └ 생성(GPU): FLUX.2-klein-4B 편집, NF4, 4단계, seed 42·43·44 → 후보 3장
       문장 = S4w 그림체 + 특징 + 피부 유지 + 같은 자세 (옷 그림이 있으면 그 옷으로 갈아입힘)
  └ 후처리: 색 맞춤(옷 바꿀 때 피부·머리만, 밝힐 때 하이라이트 한도) → 손 개수 표시
  └ 사용자가 후보 1장 고름 / 또는 부위별 고르기(얼굴·머리 후보 + 몸·옷 후보, CPU 약 18초)
```
- 시간: 후보 3장 약 100초(모델 불러오기 포함), 최고 4.05~4.9GiB.
- 모델: FLUX.2-klein-4B(Apache-2.0), 손 검출(deepghs), 분석 모델은 A와 공유.
- 자세·장면은 바꾸지 않는다(원본 자세, 콘크리트 벽 배경 고정).

## 4. 겹치거나 빠진 곳 (검증 전에 알아야 할 것)

| # | 내용 | 영향 |
|---|---|---|
| 1 | **목표 그림체는 B에만 있고, B는 화면에 없다** | 지금 앱 결과는 최종 목표(고밀도 반실사)가 아님 |
| 2 | **옷 바꾸기가 두 군데**: A는 Qwen(머리 원본 붙이기·검사·재시도), B는 FLUX(참조 2장, 검사는 손 개수만) | 어느 쪽을 제품 옷 바꾸기로 둘지 미정. B는 10명 중 6명 성공, 걸친 겉옷 남음(V001·T014) |
| 3 | **새로운 연출(기준 3)은 A에만**: B는 자세·배경 고정 | B만으로는 기준 3을 못 채움. A(연출) 다음 B(그림체)인지, B 안에 연출을 넣을지 미정 |
| 4 | **자동 검사 수준이 다르다**: A는 팔·손·특징·머리색 검사 + seed 재시도, B는 손 개수 표시만, 동일성은 사람 판정 | B의 "같은 캐릭터인가"는 자동으로 못 잼(D-205) |

## 5. 정해야 할 것 (검증 순서에 영향)

1. **제품 경로를 무엇으로 볼까** — (가) A → B 순서(Qwen으로 옷·연출, 끝에 FLUX 그림체), (나) B 하나(FLUX로 옷+그림체, 연출은 B에 추가), (다) 지금처럼 따로.
2. 그 경로로 정한 뒤 일관성 시험(같은 PC 반복 → 처음 보는 묶음 → 다른 PC)을 설계한다. 정하기 전에 시험하면 버릴 경로까지 시험하게 된다.
