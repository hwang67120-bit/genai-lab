# 기준 캐릭터 눈색 분석과 승인

## 적용 범위

기존 WD 모델의 CPU 세션 하나로 전체 이미지와 얼굴·헤어 크롭 두 개를 순서대로 분석한다.
새 탐지 모델, 홍채 분할기, 초기 RGB 생성 입력은 추가하지 않는다.
기존 얼굴·헤어 마스크 준비를 먼저 실행하고, 동일 좌표의 `VisualInputs.source`와
`identity_mask`를 사용한다. 서로 크기가 다른 마스크는 재해석하지 않고 오류로 처리한다.

크롭은 마스크의 바운딩 박스를 기준으로 한다. 머리카락 바깥을 흰색으로 지운
IP-Adapter 참조 이미지가 아니라, 기준 RGB 캔버스에서 해당 사각형을 가져온다.
여백은 0%와 15%이고, 이미지 밖은 흰색으로 채워 항상 정사각형을 유지한다.
홀수 크기와 가장자리에서도 선택 영역을 자르지 않는다.
이 캔버스는 현재 생성 크기로 정규화된 이미지이므로 원본 고해상도 홍채 분석과는 다르다.

## 점수와 추천

- WD의 필터링 전 일반 태그 점수를 보관한다. 눈색 검토는 전체 태그 상위 30개 제한과 분리한다.
- 각 크롭의 1위 눈색 원점수 0.35 이상, 1·2위 차이 0.10 이상이면서 두 크롭이 같은 태그일 때만 추천한다.
- 낮은 점수, 근소한 차이, 크롭 간 불일치, 명시적 복합색 태그 신호가 있으면 판단을 보류한다.
- 전체 이미지의 복합색 신호도 단일 색 자동 추천을 막는다. 이는 오드아이 확정이 아니다.
- 마스크 누락/빈 영역/짧은 변 32px 미만은 임의의 얼굴 위치로 대체하지 않는다.
- 원점수에 Softmax를 적용하지 않는다. 금색/노란색 태그를 임의로 추가하거나 서로 바꾸지 않는다.
- 사용 중인 WD 라벨 목록에 실제 존재하는 눈색 후보만 표시한다.

0.35, 0.10, 32px는 초기 운용 기준이며 눈색 정확도를 검증한 임계값이 아니다.
같은 이미지의 두 크롭은 상관된 입력이다. 결과 일치는 정답을 보장하지 않는다.
얼굴·헤어 박스가 너무 크거나 머리카락이 길고 홍채가 작으면 두 크롭 모두 오판할 수 있다.
낮은 해상도를 확대해도 없던 홍채 정보는 복원되지 않는다.

선택적으로 설정 파일에 다음 기준을 넣을 수 있다. 값 변경은 실제 정답 라벨 이미지로 비교한다.

```yaml
character_eye_analysis:
  threshold: 0.35
  minimum_margin: 0.10
```

## 승인 화면과 진단

기본 화면에는 유지할 특징 요약을 표시하고, 상세 수정에서 두 크롭과 눈색 선택 항목을 확인한다.
보류 상태에서는 눈색을 미리 체크하지 않는다. 사용자가 체크박스로 여러 색을 고르거나
기본 화면의 `눈색을 확정하지 않고 진행`을 확인해야 승인할 수 있다.
`눈색 모두 해제`는 선택만 지우며 생략 동의를 대신하지 않는다.
각각의 선택은 독립적이며 선택한 색을 모두 승인 태그로 전달한다.
여러 색을 선택해도 오드아이/복합색 태그를 자동 추가하지 않는다.
복합색 일반 태그는 자동 선택하지 않으며 수동 선택은 가능하다.
태그 여러 개로 홍채의 색상 위치·비율·그라데이션이나 좌우 배치를 보장하지는 않는다.
일반 태그 목록의 눈색은 중복 표시하지 않는다.
사용자 지정 성별, 의상 태그와 생성 강도는 이 분석으로 바꾸지 않는다.
태그 승인과 참조 입력 승인을 모두 통과해야 생성 모델을 실행한다.

임시 폴더 `genai-eye-review-*`에 다음 파일을 저장하며 경로는 승인 화면과 실행 로그에 표시한다.

- `head_input_0.png`, `head_input_1.png`: WD 공통 전처리에 넣은 정확한 RGB 크롭.
  ONNX 입력은 그 뒤 기존 정사각형 리사이즈 및 BGR float32 변환을 거친다.
- `eye_color_report.json`: 전체/크롭별 원점수, 전체 목록에서 빠진 이유
  (표시 임계값 미달/상위 개수 제한), 좌표, 사용 모델, 실행 장치, 추천 또는 보류 사유.
  중간 취소·실패도 기록한다. 원본 정보가 포함된 로컬 진단 자료이며 자동 삭제하지 않는다.

진단 결과는 후보의 디자인 참조 기록에도 포함한다. 진단은 눈색을 생성에 자동 확정하지 않으며,
실제 프롬프트에는 승인된 태그만 기존 경로를 통해 전달한다.
ONNX 실행 중 강제 중단은 하지 않고 각 추론 사이에 취소를 확인한다.

## 검증 방법과 한계

자동 테스트는 입력 좌표/픽셀 보존, 임계값·불일치·복합색 분기, 세션 재사용,
진단 저장, 선택 UI, 기존 승인 순서를 검증한다. 실제 WD 인식률이나 생성 품질을 측정하는 테스트는 아니다.

실제 테스트에서는 금색/파랑/보라/오드아이/작은 얼굴 등 원본을 사람이 확인한 사례를 사용하고,
전체 분석만 사용한 결과와 두 크롭 분석의 추천·오추천·보류 수를 비교한다.
다음 생성 전에는 표시된 크롭에 실제 눈이 보이는지와 승인한 눈색 태그가 최종 프롬프트에 남았는지 확인한다.
귀·꼬리의 색과 형태 개선, 좌우 홍채의 독립 분석은 이번 변경에 포함하지 않는다.

## 근거

- [Qt QCheckBox 문서](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QCheckBox.html):
  독립적으로 켜고 끌 수 있는 다중 선택을 사용하며 배타적 버튼 그룹으로 묶지 않는다.

- [WD ViT Tagger v3 모델 설명](https://huggingface.co/SmilingWolf/wd-vit-tagger-v3):
  일반 태그용 모델이며 눈색 전용 검증 모델이 아니다.
- [제작자 ONNX 추론 예제](https://huggingface.co/spaces/SmilingWolf/wd-tagger/blob/main/app.py):
  흰 정사각형 패딩, BGR 입력, 일반 태그 점수 필터링 구조를 확인할 수 있다.

두 크롭 합의와 보류 정책은 이 프로젝트의 휴리스틱이며, 모델 제작자가 보증하는 방법은 아니다.
