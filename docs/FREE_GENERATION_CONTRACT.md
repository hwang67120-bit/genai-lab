# 자유 생성 단계 계약 (2026-10-14, 사용자 승인 — 결정 5개 모두 권고대로, D-123)

## 결론부터
- 자유 생성 = **기준 이미지 + 확정된 특징표 + 요청(자세·구도·시점·배경·상황 문장, 없으면 무작위 전신 자세) → 새 그림 1장 → 특징 유지 검증 → 사람 승인**. 완성 기준 2단계(새 작품의 동일성: 특징 유지, 픽셀 아님)와 3단계(새로운 연출)를 겨냥한다.
- 편집 단계와 다른 점 하나: **머리를 원본 픽셀로 붙이지 않는다.** 동일성은 특징표(D-119~121)로 조건을 주고 결과에서 검증한다. 그래서 결과 쪽 분할이 필요하다.
- 2026-10-14 사용자 승인: 아래 7절의 5개를 모두 권고대로 확정했다(① Qwen 유지 ② 배경 허용 ③ 요청은 연출만 ④ 기준 이미지 둘 다 ⑤ 무작위 자세 고정 목록). FLOW.md 갱신 완료. 구현은 `genai_lab/free_generation_pipeline.py`(`run_free_generation`)부터.

## 1. 입력 계약
| 입력 | 내용 | 출처 |
|---|---|---|
| 기준 이미지 | 편집 단계에서 사용자가 승인한 결과(`.review.json`가 가리키는 그림). 결정 ④에 따라 원본 캔버스도 허용 | 편집 단계 |
| 특징표 | 확인 창에서 확정된 태그 항목 + 실행에서 잰 픽셀 항목(`character-features/features.json`) | D-120 |
| 성별·부위 | 확정값(저장됨) | D-106·D-111 |
| 의상 | 기준 이미지에 입혀진 옷 그대로(바꾸지 않음) | D-098 |
| 요청 문장 | 자세·구도·시점·배경·상황에 한정. 외형(머리·눈·피부·부위)·의상을 바꾸는 문장은 조건 충돌로 **거부**(이유 표시). 비어 있으면 무작위 전신 자세 | D-094·D-098, 결정 ③ |
| 무작위 자세 | 코드에 고정된 전신 자세 문장 목록에서 seed로 하나(기록됨). LLM 없음 | D-110, 결정 ⑤ |

## 2. 모델과 지시문 (결정 ①)
- 권고: 지금 쓰는 **Qwen-Image-Edit-2511(같은 worker, 6.5GiB 상한)**으로 첫 측정. image 1 = 기준 이미지, 지시문 = 조건 목록(아래). 근거: 편집 시험에서 얼굴·머리가 비교적 유지됐고(원본 붙이기 전 Qwen 출력에서 정렬이 되는 수준), 설치·메모리 검증이 끝났다. 대안(생성 모델 + 참조 어댑터)은 설치·메모리·시험이 처음부터라 첫 측정 뒤 필요하면 검토.
- 지시문은 편집과 같은 구조(D-112 조건 목록, 출처·이유 기록). 문자열은 코드 상수 + 특징표 값 + 요청 문장. LLM·RAG 없음.

조건 목록(초안):
| key | 출처 | 문장(초안) |
|---|---|---|
| keep_character | character_features | "Keep the same character: {hair length/style/colour}, {eye colour}, {head accessories}, {skin}. Keep the face the same as in image 1." (unknown 항목은 뺌) |
| keep_outfit | policy | "Keep the character's outfit exactly as in image 1 (same garments, colours and details)." |
| body_parts | user | 편집과 같은 문장(있는 것 유지·없는 것 추가 금지) |
| gender | user | 편집과 같은 문장 |
| request | user / random_pose | 요청 문장 그대로, 또는 "Full body, {random pose sentence}." |
| background | request / policy | 요청에 배경이 있으면 그 배경, 없으면 "plain pure white background"(결정 ②) |
| no_props | policy | 편집과 같음 |

## 3. 검사(자동)와 판정(사람)
자동(실패해도 결과는 보여 주고 이유를 적는다; 자동 재시도 1회(seed)는 편집과 같음):
1. 결과 분할(see-through 분할기, GPU, Qwen 종료 뒤) → 머리카락·얼굴·눈·부위 마스크.
2. 특징 검증(D-121)을 **결과 마스크**로: 머리색·눈 색·피부색 ΔE, 태그 항목, 부위 유무. 추가: 꼬리·날개 **개수**(마스크 연결 요소 수, 엄격 기준: 가려진 시작점은 정상 가정 안 함).
3. 팔·손 검사(DWPose, 결과 단독: 양팔 관절이 모두 보이거나 가려짐이 설명되는지) — 편집의 원본 대비 검사는 자세가 바뀌므로 쓰지 않는다.
4. 요청 반영 보조 검사: 요청에 자세·배경 단어가 있으면 결과 태그로 대조(참고용, 통과/실패 아님).
5. 안전: 결과 태그로 노출·아동 외형 검사(기존 정책 그대로), 걸리면 결과를 쓰지 않는다.

사람 판정(`judgement.json`, D-114 항목 + 1개):
- same_character(최종) / outfit(same·partial·different) / body_parts / pose / severe_defect / **request_followed(yes·partial·no)**.
- 작업실 결과 확인 창 체크: "같은 캐릭터로 보입니다" · "옷이 그대로입니다" · "요청한 연출이 반영됐습니다" · "심하게 이상한 곳이 없습니다".

## 4. 작업실과 외부 API
- 작업실: 편집 결과 승인 뒤 "이 캐릭터로 새 그림 만들기" 단계. 확인 창 = 기준 이미지 · 특징표(수정 가능) · 요청 문장 상자(비우면 무작위 자세 안내) · 지원 범위 경고. 결과 창 = 위 체크 4개 + 특징 검증 요약(kept/changed) 표시.
- 외부 API: 같은 공통 함수(`run_free_generation(...)`), 확인 창 대신 "검토 대기" 반환(D-110). 요청 문장은 API 입력의 한 필드.
- 거부·실패는 항상 알린다(D-104). 그림별 조정 없음.

## 5. 지원 범위와 금지
- 성인 캐릭터만, 노출 의상 규칙, 금지 입력 목록은 그대로. 요청 문장으로 노출·아동 외형을 만드는 시도는 거부.
- 편집 단계의 지원 범위 밖(앉은 자세·걸친 겉옷·기계 몸)은 **기준 이미지**에 대한 경고로 유지. 요청 문장의 자세(앉기 등)는 자유 생성에서는 허용(모델이 못 하면 결과 검사·판정으로 걸러짐).
- 처음 측정 전까지 통과율 목표를 정하지 않는다(D-118 운영 규칙: 판정 20건마다 반복 실패만 공통 규칙 수정).

## 6. 첫 측정(요청 20, 승인 뒤 작성)
- 기준 이미지: 편집 성공 사례 3명(예: N3·S04·N1 중 합성·판정 통과 결과). 요청 3종: (a) 문장 없음(무작위 자세) (b) 자세 문장 1개 (c) 배경 문장 1개 → 6장 안팎(판정 시트 4~6줄 원칙).
- 잠글 기준: 자동 특징 검증 + 사람 판정(same_character·request_followed). 수치 목표는 이 측정으로 정한다.
