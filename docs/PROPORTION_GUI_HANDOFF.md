# 원본 비율 참고 GUI 연결과 확인 순서

원본 비율 참고를 선택하면 머리 범위 지정과 윤곽 확인을 거쳐 기존 2단계 생성으로 이어진다. 기본은 OFF다. **GUI에서 실제 GPU 생성까지 이어지는 검사는 아직 하지 않았다.** 이전 내부 생성 경로의 GPU 재현과 이번 GUI의 CPU 검증을 구분한다.

## 사용자가 거치는 과정

1. 캐릭터와 의상을 선택한다. 필요할 때만 생성 설정의 **원본 비율 참고 (2단계 생성)**를 켠다.
2. 기존 입력 확인에서 성별과 의상 설명을 확인한다.
3. CPU가 원본 캐릭터의 자세를 정규화한다. 사용자는 정규화된 그림에서 머리카락과 얼굴을 사각형으로 감싼다. 파란 얼굴 기준점이 벗어나 있으면 오른쪽 클릭으로 옮긴다.
4. 별도 CPU 프로세스가 기존 SAM2 캐시로 머리 윤곽 초안을 만든다. 윤곽 겹친 그림, 원본 자세 검출 결과, 실제 전달할 윤곽을 나란히 보여 준다. 귀·뿔·옷이 섞였으면 범위를 다시 지정하거나 취소한다.
5. 사용자가 확인란을 체크하고 생성 버튼을 눌러야 2단계 생성으로 넘어간다. 확인 전에는 GPU 생성을 하지 않는다. 코·목과 윤곽 관계가 유효하지 않으면 진행 버튼이 활성화되지 않는다.
6. 기존 제품 함수가 1단계 4장 → 모델 해제 → 각 결과의 몸 바깥선과 확인한 머리 윤곽 결합 → 2단계 4장 → 흰 배경 합성을 수행한다.
7. 최종 4장을 비교하고 승인한 이미지를 저장한다. 생성 원본은 별도 보기로 남는다. 꼬리 고치기는 선택한 흰 배경 결과를 기반으로 이어진다.

원본 비율 참고는 **원본 캐릭터의 자세**를 사용한다. 외부 자세 사진을 선택하는 GUI는 이번에 연결하지 않았다. OFF는 기존 자세 미적용 생성과 흰 배경 정리를 그대로 사용한다.

## 유지한 생성 조건과 기록

| 항목 | 연결 방식 |
|---|---|
| 얼굴 참조·긍정/부정 문장 | 기존 GUI 조립 결과 유지. 새 비율 문장이나 자세 태그를 추가하지 않음 |
| 초기 얼굴 참조 강도 | ON은 잠금된 머리 윤곽 시험의 0.5, 11단계부터 0.9. OFF는 기존 0.0 유지 |
| 두 어댑터 | 골격 1.2, 스케치 0.5, 공통 0~10단계 |
| 해상도·단계·메모리 한도 | 736×1232, 28단계, reserved 6.5 GiB. 기존 내부 구현 그대로 |
| 스케치 모델 위치 | StudioRuntime의 proportion_sketch_root 한 곳에서 관리. GENAI_STUDIO_RUNTIME JSON으로 변경 가능 |
| 모델 준비 | 기존 로컬 캐시만 사용. 다운로드·패키지 설치 없음 |
| 원본·정리본 | raw와 product의 SHA를 별도 검사. ON은 기존 product를 다시 배경 처리하지 않음 |

초기 IP 0.5는 별도로 확인했다. R6은 정면 검출이지만 잠금 시험은 0.5로 실행됐으므로, 일반 자세의 nonfront 규칙으로 0.0을 선택하면 검증 조건과 달라진다. ON은 그 시험 조건을 명시적으로 사용하고 CPU 요청 검사로 고정한다.

머리 준비 기록은 실행 폴더의 `proportion-inputs/`에 남는다. 원본 사본·정규화·골격 SHA, 검출 결과, CPU 로그, 선택 사각형과 얼굴 기준점, 미승인 머리 마스크·윤곽을 보관한다. 승인 시에만 `user-confirmation.json`을 남긴다. 범위를 다시 지정하면 새 폴더를 사용한다.

생성 기록은 기존 `generation/` 아래 preflight·status·run 및 seed별 raw/product 기록을 사용한다. 승인·내보내기 기록에는 `proportion_mode`와 별도의 raw SHA·저장 이미지 SHA를 남긴다. 변경된 파일은 승인·저장하지 않는다. 실패한 2단계 대신 1단계를 성공 결과처럼 보여 주지 않는다.

## 코드 읽기 순서

| 읽기 시작점 | 입력과 결과 |
|---|---|
| studio_controller.py의 inputs_ready → proportion_pose_ready → proportion_head_ready → begin_generation | 사용자 선택과 각 CPU 작업 완료를 다음 단계에 연결 |
| studio_proportion.py의 prepare_studio_pose / prepare_studio_head / confirmed_options | 별도 CPU 프로세스 실행, 입력 식별값 검사, 명시적 승인 변환 |
| studio_proportion_worker.py의 save_pose / save_head | 기존 정규화·SAM 분할로 미승인 초안 생성. 프로세스 종료로 모델 해제 |
| studio_proportion_gui.py의 select_head_region / review_head_outline | 범위 선택, 기준점, 윤곽 검토·재선택·취소 |
| studio_generation.py의 build_request / StudioResults | 선택한 경로의 생성 요청, 원본/최종 결과 검증과 승인·저장 |

검증된 `proportion_generation.py`, `proportion_inputs.py`, `proportion_backend.py`의 생성 규칙은 수정하지 않았다.

## 확인한 근거

- Claude의 이전 내부 GPU 재현: 6 seed의 1단계·스케치·2단계·흰 배경 결과 모두 기존 시험 SHA와 일치. 최대 reserved 6.416 GiB, 전체 385초. [기록](../outputs/proportion-product-verify-20261008/results_gpu01.md).
- 이번 실제 CPU 준비: R6 원본에서 새로 만든 **정규화·골격·머리 마스크·윤곽 4/4 SHA 일치**. 승인 상태는 False, 좌표 검사 오류 없음. [대조 결과](../outputs/proportion-gui-verify-20261008/cpu-02/comparison.json).
- 최초 CPU 실행에서 분리된 골격 환경이 GUI 패키지를 불러오는 결함을 발견했다. GUI 전용 참조를 승인 함수 안으로 옮겨 해결했으며 패키지는 설치하지 않았다. 실패한 cpu-01 폴더는 보존했다.
- 화면 확인: 1024×700 작업실, 머리 범위 지정, 미승인 윤곽 확인을 오프스크린 Qt로 캡처해 글자·버튼·미리보기를 확인했다. 운영체제의 실제 마우스/화면 배율 검사는 별도다. [범위 선택](../outputs/proportion-gui-verify-20261008/head-selection.png), [윤곽 확인](../outputs/proportion-gui-verify-20261008/head-review.png).
- CPU 테스트는 기본 OFF, 요청 문장 보존, 입력 변경 거부, 승인·취소·재선택, 프로세스 분리, 표시 좌표 변환, 가짜 생성기를 통한 GUI 승인·저장, raw/product 변조 거부를 확인한다. 전체 **1,854개 통과**, 266.71초. 기존 Pillow 사용 폐기 예정 경고 2건 외 실패 없음. 이 중 새 GUI 비율 테스트는 23개다. [전체 테스트 기록](../outputs/proportion-gui-verify-20261008/pytest-full.log).

## Claude의 실제 GUI 확인 순서

GPU 작업이 종료된 상태에서 아래 명령으로 GUI를 연다. 이번 코덱스 작업에서는 GPU를 실행하지 않았다.

```powershell
& 'D:\genai-cache\venv\Scripts\python.exe' -B '\\192.168.0.109\win_g\genai-lab\gui_main.py'
```

1. 시작 시 비율 참고가 꺼져 있고, 켜면 원본 자세 사용·생성량 2배·다른 캐릭터 미검증 안내가 보이는지 확인한다.
2. 기존 R6 및 이미 확인한 일반 의상을 선택한다. 머리 사각형을 지정하고 윤곽 확인 전에는 생성이 시작되지 않는지 확인한다. 실제 시험 입력과 같은 머리 초안을 대조하려면 사각형은 `[247,28,485,292]`, 얼굴 기준점은 `[365,240]`이었다. 사용자가 그린 범위가 다르면 기존 raw SHA와 같다고 요구하지 않는다.
3. 다시 지정과 취소가 동작하는지 먼저 확인한다. 취소 시 GPU 생성 없이 입력 선택으로 돌아와야 한다.
4. 승인 후 한 묶음을 생성한다. GUI는 새로운 4개 seed와 사용자 의상 설명을 쓰므로, 기존 6 seed 시험과 SHA를 직접 비교하는 검사가 아니다. 각 입력·설정·모델·일정 기록과 결과 표시까지 연결됐는지를 확인한다.
5. 정리된 4장과 생성 원본이 각각 열리고, 확인한 정리본이 바이트 그대로 저장되는지 확인한다. 승인 전에는 저장할 수 없어야 한다.
6. 검출 실패·머리 경계 오류·모델 파일 오류·메모리 한도 초과 시 중단 이유가 보이고, 완료하지 못한 결과가 성공으로 표시되지 않아야 한다. 한 번이라도 실패하면 로그를 남기고 자동 재시도하지 않는다.

**남은 한계:** 새 GUI 경로의 실제 GPU 생성은 미검증이다. 기존 품질 근거는 R6 한 캐릭터뿐이며 바지 아랫단 색과 일부 머리 테두리 문제는 남아 있다. 머리 윤곽의 자동 검출 정확도를 보장하지 않으므로 사용자의 확인을 생략할 수 없다. 이번 변경은 커밋·푸시하지 않았다.
