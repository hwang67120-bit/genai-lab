# 요청 38 재실행 결과 — 수정한 세션으로 B2 한 줄 (2026-10-24, D-184)

> **기록 상태(사용자 10/24, D-185): 결과 일치·세션 동작 확인, 반복 준비 비용 감소, 전체 속도 개선 미확정.** 재사용 기본값은 꺼짐 유지.

## 결론

- **그림: 요청 37과 모두 같다.** ① 옷 바꾸기 raw, ② 첫 시도 raw, ② 재시도 raw, 저장 PNG — 4개 모두 SHA 일치.
- **같은 세션에서 재시도가 이어졌다.** ② 첫 시도(세션 작업 1)와 재시도(작업 2, seed 43)가 같은 작업 프로세스(pid 30588)에서 돌았다. 작업 2는 모델 파일을 다시 검사하지 않고(`files_rechecked: false`), 첫 작업의 임베딩·불러 둔 파이프라인을 그대로 썼다. 재시도 이유는 요청 37과 같다(제품 자체 재시도 1회, 추가 재시도 없음).
- **세션 정리:** 시도가 끝난 뒤 세션이 `close` 기록(작업 2개)을 남기고 끝났고, 실행 뒤 세션 프로세스가 남아 있지 않다.
- **멈춤·오류·메모리 한도 초과: 없음.** 최고 PyTorch reserved 6.36GiB(상한 6.5GiB), `memory_stopped` 없음, 실행기 종료 코드 0.
- **시간:** 재시도에서 반복하던 일(시계 전 122초·인코딩 11.6초·불러오기 75.4초·종료 8초 ≈ 217초, 요청 37 기준)이 거의 0이 됐다. 그러나 이번 실행은 세 작업 모두 생성 단계가 느렸다(단계 평균 +0.9~2.8초) — 행 전체는 6,549초로 요청 37(6,536초)과 비슷하다. **시간 차이를 재사용 효과로 해석하지 않는다**(아래 '시간' 주의).
