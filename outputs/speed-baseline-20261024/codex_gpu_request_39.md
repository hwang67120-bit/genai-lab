# GPU 시험 요청 39 — 40단계 블록 오프로드 설정 비교 (확정, 승인 대기)

## 요약

- **상태: 확정 — GPU 실행은 승인 대기.** 사용자 10/24: "다음 우선순위는 요청 39. 최신 측정치를 반영해 요청서를 확정. 서로 다른 실행 환경의 과거 시간만 비교하지 말고, 동일한 코드·런타임·입력에서 메모리 이동 설정만 바꾸도록."
- **질문:** 40단계 동안 변환기 블록을 옮기는 방식만 바꾸면 생성 시간이 줄어드는가. 그때 GPU 전체·프로세스 사용량, RAM, 결과 그림 SHA는 어떤가.
- **같게 두는 것:** 코드(이 문서를 커밋한 HEAD), 런타임(개발 환경 `qwen-test-venv`), 입력(같은 요청 파일 — `settings.offload`만 다름), seed 42, 40단계, CFG 4, 896×1184, 6.5GiB 상한. **세션 재사용은 쓰지 않는다**(단일 작업 경로).
- **새 품질 시험이 아니다.** 결과 그림은 SHA로만 비교한다.
- 예상 시간: 한 번에 약 33~35분(요청 38 재실행의 같은 요청: 작업 프로세스 1,941초 + 시작 전 132초) × 4번 ≈ 2시간 20분.

## 판정 규칙 (실행 전에 고정)

- **결과 SHA:** 기준(1·4)은 기준 요청 raw와 같아야 한다 — 다르면 같은 조건이 아니므로 **멈춘다**. 측정 설정(2·3)이 다르면 '불일치 — 원인 조사'로 적고 품질 실패·성공으로 판정하지 않는다(그 설정은 채택 후보에서 빠진다 — 계산 결과가 바뀌는 변경이므로).
- **시간:** 2·3의 단계 평균을 1과 4 **둘 다**와 비교한다. 1과 4의 차이(실행 사이 변동)보다 작거나 단계당 3초 이내면 '차이 확인 안 됨'으로 적는다.
- **메모리:** 2·3은 기준보다 PyTorch·장치 전체·RAM이 늘 수 있다. 늘어난 만큼을 그대로 적는다. 장치 전체가 8GiB에 닿거나 공유 GPU 메모리가 크게 늘면 채택 후보에서 뺀다(속도보다 안정이 먼저).
- 채택은 사용자 결정이다. 결과가 좋아도 제품 기본값을 바꾸지 않는다.

## 중단 규칙

- 멈춤·실패·시간 초과(한 번 90분)·**메모리 한도 초과(`memory_stopped` 또는 PyTorch reserved > 6.5GiB)** → 그 경우를 기록하고 **거기서 멈춘다.** 실행기가 스스로 멈춘다.
- **설정을 완화하거나(상한을 올리거나 다른 설정으로 바꾸거나) 추가 실행하지 않는다.** 실패한 경우를 다시 돌리지 않는다.
- 코드를 고쳐야 할 것 같으면 고치지 말고 멈추고 보고한다.

## 측정 한계 (보고에 그대로 적는다)

- 경우마다 한 번씩만 돈다 → 실행 사이 변동의 크기는 1과 4의 차이 하나로만 본다(분포 아님).
- 디스크 캐시를 비우거나 데우지 않는다. 첫 실행(1)은 캐시가 차갑고 뒤 실행은 따뜻할 수 있다 — **시작 전 구간·문장 인코더 읽기 시간이 영향을 받는다.** 40단계 생성은 가중치가 이미 RAM에 있어 디스크 캐시의 영향이 작다고 보지만 확인하지는 않는다. 그래서 비교는 **생성 단계 시간**을 주로 쓰고, 전체 시간 차이를 설정 효과로 보지 않는다.
- GPU 온도·클럭·다른 프로그램의 GPU 사용은 조절하지 않는다(장치 전체 값으로만 본다).
- 프로세스별 GPU는 Windows 카운터 약 2초 간격이라 짧은 최고값을 놓칠 수 있다. PyTorch reserved(`memory.json`)를 함께 본다.
- 이 결과는 한 PC(RTX 4060 8GB, RAM 48GB)·한 입력(896×1184)에 대한 것이다.
